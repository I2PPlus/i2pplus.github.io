    Cache data for EdDSA key blinding as specified in Proposal 123: New NetDb Entries.

    BlindData provides the infrastructure for cryptographic key blinding in I2P:

    • Manages blinded and unblinded EdDSA signing key pairs
    • Supports multiple authentication methods for encrypted LeaseSets
    • Caches computed blinded keys and related metadata
    • Handles time-based key rotation and expiration
    • Generates blinded destination addresses (.b32.i2p)

    Key Components:

    • Key Blinding: Transforms clear signing keys into blinded equivalents
    • Authentication: Supports DH, PSK, and no-authentication modes
    • Caching: Stores computed values to avoid expensive recalculation
    • Address Generation: Creates blinded .b32 addresses for services

    Authentication Types:

    • AUTH_NONE - No authentication required
    • AUTH_DH - Diffie-Hellman key exchange for per-client keys
    • AUTH_PSK - Pre-shared key authentication

    Usage Scenarios:

    • Encrypted LeaseSets: Generate blinded keys for restricted access
    • Destination Blinding: Create anonymous service endpoints
    • Access Control: Implement authentication for private services
    • Key Rotation: Manage time-based blinded key updates

    Security Considerations:

    • Blinded keys provide unlinkability between clear and blinded identities
    • Authentication data must be securely stored and transmitted
    • Key rotation intervals should balance security and usability
    • Proper validation of blinded signatures is essential

    Implementation Status: PRELIMINARY - Subject to change as proposal evolves.
