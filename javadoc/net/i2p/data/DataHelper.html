net.i2p.data

Class DataHelper

  • java.lang.Object
    • net.i2p.data.DataHelper

  • public class DataHelper
extends Object
    Comprehensive utility class for I2P data structure serialization, encoding, and manipulation.

    DataHelper provides essential utilities for working with I2P data structures:

    • Serialization: Read/write primitive types to/from streams
    • Encoding: Base64 and Base32 encoding/decoding
    • Validation: Data format verification and bounds checking
    • Conversion: Between different data representations
    • Utilities: Common operations on collections and arrays

    Core Operations:

    • Primitive I/O: readLong(), writeLong(), readString(), writeString()
    • Base64: encode(), decode() with filesystem-safe variants
    • Base32: encodeBase32(), decodeBase32() for addresses
    • Properties: readProperties(), writeProperties() for metadata
    • Collections: toMap(), toString() for data structures

    Encoding Support:

    • Base64: Standard and URL-safe variants with/without padding
    • Base32: RFC 3548 compliant for .b32.i2p addresses
    • Hex: Hexadecimal encoding for debugging and display
    • UTF-8: String encoding with proper byte handling

    Data Structure Support:

    • Arrays: Efficient reading/writing of byte arrays
    • Collections: Map, List, and Set serialization
    • Dates: Timestamp handling with proper timezones
    • Properties: Key-value pair serialization

    Validation and Safety:

    • Bounds Checking: Prevent buffer overflows and underflows
    • Null Handling: Safe null value processing
    • Size Limits: Protection against excessive memory allocation
    • Format Validation: Data structure integrity checks

    Performance Features:

    • Buffer Reuse: ByteArrayStream for efficient operations
    • Caching: Frequently used constants and computations
    • Bulk Operations: Optimized for large data sets
    • Memory Management: Careful allocation and cleanup

    Common Use Cases:

    • Network Protocol: I2NP message serialization
    • Configuration: Properties file handling
    • Address Display: Base32 encoding for .b32.i2p
    • Data Storage: File format serialization
    • Debugging: Hex dumps and data inspection

    Thread Safety:

    • Static Methods: All operations are thread-safe
    • No State: Class maintains no mutable instance state
    • Immutable Data: Input data is not modified

      • compress

        public static byte[] compress(byte[] orig)
        Compress the data and return a new GZIP compressed byte array. The compressed data conforms to RFC 1952, with a 10-byte gzip header and a 8-byte gzip checksum footer. Prior to 0.9.29, this would return a zero-length output for a zero-length input. As of 0.9.29, output is valid for a zero-length input also. As of 0.9.47, this uses a level of MEDIUM_COMPRESSION, which is a good space/speed tradeoff. Prior to that, it used MAX_COMPRESSION.
        Returns:
        null if orig is null
        Throws:
        IllegalArgumentException - if input size is over 40KB
        IllegalStateException - on compression failure, as of 0.9.29

      • readProperties

        public static Properties readProperties(InputStream rawStream)
                                 throws DataFormatException,
                                        IOException
        Read a mapping from the stream, as defined by the I2P data structure spec, and store it into a Properties object. A mapping is a set of key / value pairs. It starts with a 2 byte Integer (ala readLong(rawStream, 2)) defining how many bytes make up the mapping. After that comes that many bytes making up a set of UTF-8 encoded characters. The characters are organized as key=value;. The key is a String (ala readString(rawStream)) unique as a key within the current mapping that does not include the UTF-8 characters '=' or ';'. After the key comes the literal UTF-8 character '='. After that comes a String (ala readString(rawStream)) for the value. Finally after that comes the literal UTF-8 character ';'. This key=value; is repeated until there are no more bytes (not characters!) left as defined by the first two byte integer. As of 0.9.18, throws DataFormatException on duplicate key
        Parameters:
        rawStream - stream to read the mapping from
        Returns:
        an OrderedProperties
        Throws:
        DataFormatException - if the format is invalid
        IOException - if there is a problem reading the data
