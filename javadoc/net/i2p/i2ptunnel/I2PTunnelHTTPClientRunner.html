    public class I2PTunnelHTTPClientRunnerextends I2PTunnelRunner
    HTTP client runner that filters response headers to enforce the "Connection: close" header, ensuring browsers treat the connection as non-persistent, even if the server doesn't comply.

    This class is internal and not part of a stable public API.

    Implements proper resource cleanup, supports optional keep-alive for both I2P and browser sockets, and uses background threading for non-blocking socket closure when appropriate.

    Thread Safety: This class is not thread-safe. It is expected to be used by a single connection thread.

      • trackInitialResponseDeadline

        protected boolean trackInitialResponseDeadline()
        Whether this runner type arms the first-response deadline watchdog. False in the base runner so idle long-lived sessions (HTTP CONNECT, SOCKS, IRC, server-side tunnels) are never torn down for silence; the HTTP request/response runner overrides it to true. For CONNECT the remote proxy's 200 response would retire the watchdog anyway, but the default keeps the deadline strictly scoped to request/response flows.

        True here: an HTTP request/response strictly precedes its response, so a peer that never sends the first byte must be torn down by the initial-response deadline instead of hanging the runner forever (read timeouts are disabled for HTTP tunnels and the body stall timeout is only armed after the first byte).

        Overrides:
