      • runOnIO

        private void runOnIO(I2PTunnelHTTPServer.Sender s, String desc) throws IOException
        Run a Sender on the dedicated I/O pool with idle-based stall detection. The handler thread polls Future.get() in short slices and cancels only after I2PTunnelHTTPServer.ioStallTimeoutMs with no read progress. A total-timeout Future.get would kill any transfer longer than the stall window (a multi-minute I2P download at hundreds of KB/s), which is expected latency — not a stall. On true idle the Sender thread is interrupted (breaking any blocking read()), and an IOException propagates to the finally-block cleanup.

        Used for keepalive responses (must wait before the next request) and as a fallback when async handoff is not taken.

        Parameters:
        s - the Sender to run
        desc - descriptive name for error messages
        Throws:
        IOException - if the transfer goes idle for the stall timeout, fails, or the pool rejects the task

      • scheduleBodyWatchdog

        private void scheduleBodyWatchdog(I2PTunnelHTTPServer.Sender body, AtomicBoolean finished, Runnable finish, InputStream browserin, OutputStream browserout, InputStream serverin, OutputStream serverout)
        Attach a I2PTunnelHTTPServer.BodyWatchdog to a detached async body. The poll interval is fixed at I2PTunnelHTTPServer.BodyWatchdog.POLL_MS (the SimpleTimer2 5s minimum); the stall window itself is I2PTunnelHTTPServer.ioStallTimeoutMs. The watchdog cancels itself on the next tick after finishTransfer sets the finished flag, so it never outlives the connection.
        Parameters:
        body - detached Server-to-Client Sender
        finished - request-wide finish-once flag
        finish - idempotent finish shared with the handoff
        browserin - browser-side request stream; may be null
        browserout - browser-side response stream; may be null
        serverin - I2P-side response body stream; may be null
        serverout - I2P-side request stream; may be null
