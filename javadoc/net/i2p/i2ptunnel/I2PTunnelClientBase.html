    public abstract class I2PTunnelClientBaseextends I2PTunnelTask implements Runnable
    Abstract base class for I2P client tunnels with common functionality.

    Manages I2PSocketManager creation, local server socket setup, connection threading, and framework for shared and non-shared client tunnels. Handles SSL configuration, connection timeouts, and provides abstract methods for connection-specific implementations.

    Extended by specific tunnel types like HTTP clients, SOCKS proxies, and standard TCP tunnels.

        static final int MAX_TIMEOUT_FAILOVER
        Legacy cap on consecutive connect timeouts before abandoning tunnel failover. The leg walk no longer stops on a timeout count — every configured leg is tried while the pool has capacity — so the walk is now bounded by REQUEST_CONNECT_DEADLINE_MS instead. Retained as a documented legacy bound.

      • REQUEST_CONNECT_DEADLINE_MS

        static final long REQUEST_CONNECT_DEADLINE_MS
        Single wall-clock budget for establishing one proxied request. Naming lookups, every tunnel-failover leg, retry sleeps, and outer connect re-walks all draw from one deadline computed from this budget instead of each keeping an independent limit, so a quantity-4 leg walk plus outer retries can no longer stack well past two minutes before the request gives up.

      • MIN_CONNECT_LEG_MS

        static final long MIN_CONNECT_LEG_MS
        Minimum remaining budget for starting one connect leg. Streaming floors connect timeouts at 10s (CONNECT_TIMEOUT_FLOOR_MS), so a leg with less than this left is guaranteed to be cut short — it can only burn the shared deadline on a doomed attempt. The walk skips such a leg instead.

      • POOL_BUILD_DEADLINE_GRACE_MS

        static final long POOL_BUILD_DEADLINE_GRACE_MS
        One-shot deadline extension granted while the outbound tunnel pool is still building (poolState() == 0) when the shared budget runs out. No connect leg can succeed before the pool's first tunnel lands; a healthy first build completes inside this window, so expiring the request at the 120s mark would discard a request whose pool was seconds from ready. At most one extension per request, keeping the worst case at REQUEST_CONNECT_DEADLINE_MS + this value.

      • DEFAULT_MAX_CONNECTIONS

        public static final int DEFAULT_MAX_CONNECTIONS
        Default cap on concurrently handled client connections.

        The accept/connect path runs on an unbounded I2PTunnelClientBase.BlockingRunner pool, so a flood of inbound peer connections (e.g. tracker announces/scrapes) can spawn unlimited parallel connect attempts - each with its own retry loop - starving legitimate browsing streams. A hard concurrent-process cap sheds excess inbound load instead of amplifying it.

        I2PSocket createI2PSocket(Destination dest, I2PSocketOptions opt, long deadlineMs) throws I2PException, ConnectException, NoRouteToHostException, InterruptedIOException
        Create a new I2PSocket bounded by a shared request deadline.

        The HTTP proxy threads one request-scoped deadline through naming, the failover walk, retry sleeps, and outer retries (REQUEST_CONNECT_DEADLINE_MS). The walk starts no leg once the deadline has passed and shortens each leg's connect timeout to the remaining budget, so the whole operation cannot exceed the deadline by a full connect timeout.       • legConnectTimeoutMs

        static long legConnectTimeoutMs(long requestedMs, long deadlineMs, long nowMs)
        Compute the connect timeout to apply to one failover leg under a shared deadline. Pure decision. No clock access, safe for unit tests.

      • extendDeadlineForBuildingPool

        static long extendDeadlineForBuildingPool(long deadlineMs, long nowMs, int poolState, boolean alreadyExtended)
        One-shot deadline extension for a request whose outbound tunnel pool is still building when the shared deadline runs out. Pure decision. No clock access, safe for unit tests.

        Pool state 0 means the pool exists with no valid tunnel yet but builds are in progress: no connect leg can succeed until one lands, and a healthy first build finishes well inside the grace window.         Returns:
