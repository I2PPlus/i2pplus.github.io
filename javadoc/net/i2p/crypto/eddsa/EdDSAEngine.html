      • ONE_SHOT_MODE

        public static final AlgorithmParameterSpec ONE_SHOT_MODE
        To efficiently sign or verify data in one shot, pass this to setParameters() after initSign() or initVerify() but BEFORE THE FIRST AND ONLY update(data) or update(data, off, len). The data reference will be saved and then used in sign() or verify() without copying the data. Violate these rules and you will get a SignatureException.

        private static final byte[] ORDER_LITTLE_ENDIAN

      • sBuf

        private byte[] sBuf
        Reusable buffer for the S half of a signature, to avoid allocating a fresh array for every verification. Only valid within one call, and never retained by any callee. Like the digest, baos and oneShotBytes state this class already keeps, it assumes the instance is used by one thread at a time - callers that care create a fresh engine per operation.

      • isBelowOrder

        private static boolean isBelowOrder(byte[] s)
        Is the 32 byte little-endian value in s strictly less than EdDSABlinding.ORDER?

        Equivalent to _ble.toBigInteger(s).compareTo(EdDSABlinding.ORDER) < 0 without allocating a BigInteger and a reversed copy of the input. This is a fixed 32 iteration borrow chain: every byte is read and every byte is subtracted, and the only carry is folded into the next iteration with arithmetic, so there is no data-dependent branch or memory access. That makes it strictly better than BigInteger.compareTo(), which exits early on the first differing magnitude word. A short-circuiting byte compare would be a timing oracle here; DataHelper.eq()/MessageDigest.isEqual(byte[], byte[]) are equality tests and cannot express an ordering, so they don't apply.

        Parameters:
        s - the value to test, 32 bytes, little-endian
        Returns:
        true if s is less than the group order
