    Shared NIO selector-based handler pool for SAM v3 control connections.

    Replaces the thread-per-connection model for SAM v3 handlers with a single selector thread reading all handler sockets and dispatching complete command lines inline. Commands are processed serially per-connection in the order they arrive. PING/PONG keepalive and idle timeout are handled at the pool level so individual handlers do not consume threads while waiting for input.

      • queueTeardown

        static boolean queueTeardown(Executor pool, Runnable teardown)
        Hand a handler teardown to a pool that is allowed to block, instead of running it wherever the disconnect was noticed.

        stopHandling() runs SAMv3Handler.die(), which waits up to 10 seconds for a session's threads to exit. The selector thread is shared by every pooled connection, so running a teardown on it stalls all of them behind one slow client. Extracted so the hand-off itself is testable.

        Parameters:
        pool - the executor to hand the teardown to
        teardown - the teardown to run
        Returns:
        true if the pool accepted it; false if it was rejected, in which case the caller must still run the teardown somewhere

      • runTeardown

        void runTeardown(Runnable teardown)
        Run a handler teardown off the thread that noticed the disconnect, on the pool built for that work - not on the connector pool, whose four threads are what a user-facing STREAM CONNECT or FORWARD waits on.

        Falls back to running the teardown on the caller's thread only when the teardown pool has already shut down and there is nowhere left to hand it to. See queueTeardown(Executor, Runnable) for why the hand-off matters.

        Parameters:
        teardown - the teardown to run

      • getConnectors

        ThreadPoolExecutor getConnectors()
        Thread pool for blocking STREAM CONNECT operations. Fixed pool of 4 daemon threads with an unbounded work queue. Limits concurrent connects to prevent overwhelming the streaming layer while keeping pool workers unblocked. Excess CONNECTs queue up and are dispatched as connector threads become available.

        Handler teardowns do not run here - they have their own pool, because a teardown waits up to 10 seconds for a session's threads and would take a connect slot with it.

        Returns:
        the shared pool of four daemon threads that run blocking STREAM CONNECT operations

      • getTeardowns

        ThreadPoolExecutor getTeardowns()
        Thread pool that runs handler teardowns off the selector thread. Fixed pool of 2 daemon threads with an unbounded work queue, sized apart from the connector pool so a slow die() cannot stall new connections. runTeardown() hands its teardowns here, so this is the one place that pairing is stated.
