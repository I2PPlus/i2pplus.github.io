    java.lang.Object
    net.i2p.router.JobQueue
    public class JobQueueextends Object
    Prioritizes and executes router jobs with preference for earlier scheduled tasks. Manages job queues, timing, and thread pool execution for router-internal operations only.

    For use by the router only. Not to be used by applications or plugins.

      • addJobToTop

        public void addJobToTop(Job job)
        Enqueue the specified job at the top of the queue, ahead of all normal-priority jobs. The job is exempt from the drop policy and its scheduled start time is overridden to run immediately. Any existing copy in the timed or ready queues is removed first, so promotion can never cause the job to run twice.
        Parameters:
        job - the job to promote to the front of the queue

      • getMaxLag

        public long getMaxLag()
        Maximum lag time for jobs waiting in the queue. This is the delay between when the earliest job was supposed to start and the current time. Uses peek() on each FIFO queue — the head element is the oldest and therefore has the highest lag.
        Returns:
        maximum lag in milliseconds, or 0 if all queues are empty

      • getMaxActiveJobDuration

        public long getMaxActiveJobDuration()
        Maximum duration of currently running jobs. This measures how long active jobs have been executing, which is important when all runners are busy but queue is empty.
        Returns:
        max duration in milliseconds of any currently running job, or 0 if no jobs running

      • getAvgLag

        public long getAvgLag()
        Average lag time for jobs waiting in the queue. This is the average delay between when jobs were supposed to start and the current time across all ready jobs.

        Uses weakly-consistent iteration on each BlockingQueue — concurrent additions/removals may be missed or double-counted, but the result is a sufficient approximation for diagnostics and scoring.

        Returns:
        average lag in milliseconds, or 0 if queue is empty

        public boolean isAlive()
        Check if the job queue is currently alive and processing jobs.       • getTestJobCount

        public int getTestJobCount()
        Count the number of TestJob instances currently queued in the job queue. This includes both ready jobs and timed jobs waiting to be executed.

        O(1): maintained by the queue-mutation helpers, because the pumper samples it on every pass and walking three collections under _jobLock was measurable work for a stat that only feeds a graph.

        Counts a pumper-promoted job in _timedJobsReady as queued. Those jobs are due to run now, so omitting them understated the queue; this matches the jobQueue.testJobCount description and the admission check in addJob(Job), which treats them as ready.

        Returns:
        the total number of TestJob instances in the queue
