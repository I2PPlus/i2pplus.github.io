    A latency baseline for one transport, built from the round trip times that transport has actually measured.

    Purpose: an absolute millisecond threshold cannot judge two transports at once. A threshold tuned for NTCP2 is either unreachable for SSU2, so every SSU2 peer looks slow, or so loose for NTCP2 that it admits links that cause build timeouts. The penalty is structural rather than a property of the peer, so the peer is excluded for carrying the protocol it happens to speak. Per-protocol baselines remove that: each transport is judged against what it can achieve on its own.

    The baseline is the mean of the SAMPLES_FOR_BASELINE fastest retained samples, not of all of them. This is the same estimator TCP uses to derive its floor for retransmission timeout, and it is chosen here for one property: it tracks what the transport has recently achieved. A mean over every sample would follow the population upward as the network degrades, so the bar would relax precisely when quality matters most, and a peer becoming slow would be scored against a baseline that had already drifted to accommodate it. Keying on the floor keeps the bar steady while the tail is allowed to move.

    The trade-off is deliberate and worth stating: the floor only ever reflects the best links seen recently, so if an entire path to one protocol degrades, the baseline stays optimistic and its peers score worse. That is the intended reading - degradation should show up - but it means the baseline is not relative to current conditions.

    Instances are not thread-safe. The intended lifecycle is one instance per transport, built once per sampling cycle from that cycle's measurements, then read for the duration of the cycle.

      • getClampedBaselineMs

        public long getClampedBaselineMs(long floorMs, int multiple)
        The calibrated floor, clamped so it can never fall below floorMs / multiple.

        The clamp is the guard against a freakishly low population tightening the bar below what an absolute rule would have used. A single 1 ms sample among fifty would otherwise put the baseline at a few milliseconds and make the multiple threshold far stricter than the absolute floor it replaces. With the clamp the calibrated bar is always at least as permissive as the absolute one, so introducing calibration can only widen the set of qualifying peers, never narrow it.

        Parameters:
        floorMs - the absolute low-latency floor in ms
        multiple - the multiple of the baseline a peer must stay under
        Returns:
        the clamped baseline in ms, or -1 if unknown
