    NTCPTransport, TransportImpl, UDPTransport
    public interface Transport
    Core interface for I2P transport protocols.

    This interface defines the contract for all transport implementations that enable I2P routers to communicate with each other. Transports handle message sending, receiving, peer management, and network address configuration.

    Transport Types:

    • NTCP - Stream-based TCP transport with encryption
    • UDP - Datagram-based transport with reliability
    • SSU - Sessionless UDP for introduction

    Implementation Requirements:

    • Implement all interface methods for proper functionality
    • Handle both IPv4 and IPv6 addressing
    • Support concurrent message sending and receiving
    • Provide proper error handling and logging
    • Integrate with TransportManager lifecycle

    Plugin Development: To implement a new transport plugin:

    1. Implement this interface and required base classes
    2. Add transport to TransportManager.startListening()
    3. Ensure proper configuration and discovery
    4. Test with existing I2P network compatibility

    Note: API is subject to change. Please contact the I2P development team if you're writing a new transport or transport plugin to ensure compatibility and guidance.

        TransportBid bid(RouterInfo toAddress, int dataSize)
        Request to send a message to the specified router.

        This method allows the transport to evaluate whether it can and wants to send a message to the target router. The transport may decline based on current load, peer reputation, or transport-specific constraints.

        Parameters:

        Returns:
        a TransportBid containing send details, or null if unwilling to send

      • send

        void send(OutNetMessage msg)
        Asynchronously send a message to the specified peer.

        This method handles the actual message transmission. If the send operation succeeds, it queues up any follow-up jobs defined in msg.getOnSendJob() and registers them with OutboundMessageRegistry (if the message has a reply selector). If the send fails, it queues up any failure handling jobs from msg.getOnFailedSendJob().

        The method should return immediately and perform the actual sending asynchronously to avoid blocking the calling thread.

        Parameters:
        msg - the message to send, containing destination, payload, and callbacks

      • getEstimatedRTT

        default int getEstimatedRTT(Hash peer)
        The transport's own measured round trip time to a peer.

        This is the direct link cost of reaching the peer, which is what first-hop selection needs. It is deliberately distinct from PeerProfile.getTunnelTestTimeAverage(), which is the round trip through an entire multi-hop tunnel and is not a valid measure of one hop.

        Implementations that do not track latency return 0, which callers must read as unknown rather than as zero latency. Unknown is never treated as slow.

        Parameters:
        peer - the peer to measure
        Returns:
        the estimated round trip time in ms, or 0 if not measured

      • getEstimatedRTTTime

        default long getEstimatedRTTTime(Hash peer)
        When getEstimatedRTT(Hash) last measured this peer, on the router clock.

        A transport that measures once per session and then holds the number - NTCP2, whose only round trip is its handshake - returns the handshake time, not the present. Reporting now instead would let a reading hours old pass as fresh and keep resetting the profile's staleness window, which is what stops it from ever expiring.

        A transport whose reading is refreshed by ongoing traffic, such as SSU2 on acknowledgement, has nothing to report: the value it returns is current by construction, and it returns RTT_TIME_CURRENT.

        Parameters:
        peer - the peer to look up
        Returns:
        the timestamp of the measurement in ms, RTT_TIME_CURRENT when the reading is always current, or RTT_TIME_UNKNOWN when the transport does not track one

      • externalAddressReceived

        void externalAddressReceived(Transport.AddressSource source, byte[] ip, int port)
        Notify transport of an external address change event.

        This method informs the transport that its external address has changed due to various sources like UPnP discovery, interface changes, or configuration updates. The transport should evaluate whether to accept this change based on the source and current state.

        Call Conditions:

        • Should NOT be called if IP didn't change from source's perspective
        • Should NOT be called for local/private addresses
        • May be called multiple times (once for IPv4, once for IPv6)
        • Transport should validate source before accepting

        Timing: Can be called before startListening() to set initial address, or after transport is already running.

        Parameters:
        source - the address source reporting the newly seen address
        ip - the new external IP address (IPv4 or IPv6), may be null to indicate IPv4 failure or port-only change
        port - the new external port number, 0 if unknown or unchanged

      • externalAddressRemoved

        void externalAddressRemoved(Transport.AddressSource source, boolean ipv6)
        Notify a transport of an external address change. This may be from a local interface, UPnP, a config change, etc. This should not be called if the ip didn't change (from that source's point of view), or is a local address. May be called multiple times for IPv4 or IPv6. The transport should also do its own checking on whether to accept notifications from this source.

        This can be called after the transport is running.

        Parameters:
        source - the address source whose address has gone away
        ipv6 - true for IPv6, false for IPv4

        int getRequestedPort()
        The internal port that the transport wants forwarded via UPnP.

      • wasFailsafeClosed

        boolean wasFailsafeClosed(Hash peer, long withinMs)
        Whether this transport closed a session to the given peer for idleness within the given window.

        True means this router declined to keep talking to the peer, which is not the same as the peer having gone away. Transports without a notion of closing idle sessions return false, and callers must read that as "no information" rather than as evidence about the peer.

        Parameters:
        peer - the peer to ask about, non-null
        withinMs - how far back counts as recent in ms; non-positive means nothing is recent
        Returns:
        true when this transport closed a session to the peer that recently

      • isConnecting

        boolean isConnecting(Hash peer)
        Check if a connection attempt is in progress for the given peer.

        This method returns true when the transport has accepted a message for this peer and initiated a connection handshake, but the handshake has not yet completed. Unlike isEstablished(Hash), which only returns true for fully-connected peers, this method detects connections that are still being set up.

        Used by the tunnel build system to distinguish between peers that are genuinely unreachable vs. peers that just need more time for the initial NTCP2/SSU2 handshake.

        Parameters:
        peer - hash of the peer to check
        Returns:
        true if a connection attempt is in progress

      • forceDisconnect

        void forceDisconnect(Hash peer)
        Force immediate disconnection from specified peer.

        This method commands the transport to immediately terminate the connection to the specified peer. Unlike mayDisconnect(Hash), this is not advisory - the transport must comply and disconnect as soon as possible.

        Use Cases:

        • Peer misbehavior or protocol violations
        • Router shutdown or transport shutdown
        • Network topology changes requiring disconnection
        • Administrative or manual disconnection requests
        Parameters:
        peer - hash of the peer to forcefully disconnect from
