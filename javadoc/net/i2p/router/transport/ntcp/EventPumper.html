    class EventPumperextends Object implements Runnable
    The main NTCP NIO event loop thread responsible for high-throughput, low-latency handling of inbound and outbound NTCP connections using non-blocking I/O.

    This class is optimized for minimal overhead and maximum event dispatch efficiency. All hot paths (e.g., processRead(SelectionKey), processWrite(SelectionKey), runDelayedEvents()) avoid synchronization, allocations, and unnecessary syscalls.

    Key performance characteristics:

    • Fixed 200ms selector timeout for consistent latency
    • Immediate wakeup() on pending I/O
    • Duplicate-free write request tracking via ConcurrentHashSet
    • Spin detection: yields briefly when select() returns repeatedly without blocking
    • Failsafe iteration every 2 seconds to clean stale connections
    • Efficient buffer pooling with bounded size

      • acquireWriteBuf

        public static byte[] acquireWriteBuf()
        Acquire a fixed-size NTCP2 frame buffer for the next data-phase frame. High-frequency path in the writer threads.

        The caller writes the frame into the returned buffer and hands it to the connection via wantsWrite(data, 0, len). The pumper later returns it to the pool via releaseWriteBuf(byte[]) once the frame has fully drained to the socket; error paths in the producer must release it instead.

        Returns:
        a byte array of length WRITE_BUFSIZE

      • releaseWriteBuf

        public static void releaseWriteBuf(byte[] data)
        Return an NTCP2 frame buffer to the pool.

        Only buffers of the exact WRITE_BUFSIZE class are accepted, so handshake and termination buffers that happen to drain through the same write path never enter this pool. The buffer is discarded, not pooled, when the cache is full.

        Parameters:
        data - the buffer to return, or null (no-op)

      • perSecond

        static int perSecond(int count, int elapsedSeconds)
        Convert a raw window counter into a per-second rate.

        Both pumper loop stats describe rates ("loops/s"), so both must be divided by the window length. Reporting the raw idle count instead made that series read about five times too large on the five-second window, which also made it uncomparable with the total-loop series it is meant to be read against.

        Parameters:
        count - events observed across the window
        elapsedSeconds - window length in seconds, coerced to at least 1
        Returns:
        the per-second rate, truncated toward zero

      • publishLoopRates

        static void publishLoopRates(java.util.function.BiConsumer<String,Long> publish, int loopCount, int idleLoopCount, int elapsedSeconds)
        Publish both pumper loop rates, normalised by the same window.

        Both stats are documented as a rate, so both are divided here rather than at the call site. Publishing them from one place is deliberate: the original defect was a raw idle count published beside a normalised total, which no test of either helper alone could catch, because the error lived in which value reached the stat manager.

        Parameters:

        loopCount - total iterations observed across the window
        idleLoopCount - no-work iterations observed across the window
        elapsedSeconds - window length in seconds

      • evaluateInboundFlood

        static EventPumper.InboundFloodDecision evaluateInboundFlood(long now, int rawCurrentCount, int rawLastCount, long periodStart, boolean hasCapacity, int maxConnections, int currentConnections, RandomSource random)
        Decide whether an inbound NTCP connection should be probabilistically rejected because the accept rate is spiking well above the recent baseline while the router is already heavily loaded with connections.

        This is the pure decision half of shouldAllowInboundEstablishment(). It performs no locking and takes raw counters instead of a Rate, so the hot accept path never blocks on the global Rate monitor. The arithmetic is pinned by InboundFloodDecisionTest in the router test tree.

        Parameters:
        now - router clock time in milliseconds
        rawCurrentCount - events so far in the current (partial) rate period
        rawLastCount - events in the most recent full rate period
        periodStart - start time of the current rate period, milliseconds
        hasCapacity - true if the transport reports spare bandwidth, which relaxes the flood threshold vs. punishing when saturated
        maxConnections - the transport connection ceiling
        currentConnections - the live peer connection count
        random - source of randomness for the probabilistic decision
        Returns:
        the decision; never null

      • writeOneBuffer

        static EventPumper.WriteState writeOneBuffer(NTCPConnection con, SocketChannel chan) throws IOException
        Write one queued buffer to the socket. Empty head buffers are discarded and the drain continues; a zero-byte write means the socket buffer is full and the caller must keep OP_WRITE interest, unless the queue is empty and fully drained, in which case interest can be dropped.

        Buffers are returned to the pool once their frame is fully flushed. Only the fixed-size NTCP2 frame class re-enters the pool; smaller handshake and termination buffers are left alone. The release happens on the pumper thread immediately after NTCPConnection.removeWriteBuf(ByteBuffer) so a frame array can never be reused while any producer still references it.

        Parameters:
        con - the connection being drained
        chan - the connection's socket channel
        Returns:
        the EventPumper.WriteState governing the next step in the drain loop
        Throws:
        IOException - if the channel write fails

      • releaseDrainedWriteBuf

        static void releaseDrainedWriteBuf(ByteBuffer buf)
        Return a fully drained NTCP2 frame buffer to the pool.

        Invoked from writeOneBuffer(NTCPConnection, SocketChannel) on the pumper thread right after the buffer leaves the connection's write queue. Only arrays of the pooled WRITE_BUFSIZE class are returned; everything else (handshake, termination, and legacy buffers) is ignored.

        Parameters:
        buf - the drained buffer, wrapped around a frame array

      • classifyConnectException

        static EventPumper.ConnectErrorKind classifyConnectException(Exception e)
        Classify an exception thrown during outbound connect setup. Genuine channel-state failures from the socket layer (already-connected, connect pending, not-yet-connected) mean the peer or the connect attempt is at fault and the peer should be marked unreachable. Anything else - local configuration misuse (blocking-mode channel), invalid arguments, or an internal defect - only tears down the local connection so an internal bug never blames (and blacks out) a healthy remote peer.

        Classified by exception type rather than class-name substrings: name matching silently misreads e.g. NotYetConnectedException as OTHER and blames a peer for a local IllegalBlockingModeException.

        Parameters:
        e - the exception to classify (never null)
        Returns:
        the EventPumper.ConnectErrorKind for this exception
