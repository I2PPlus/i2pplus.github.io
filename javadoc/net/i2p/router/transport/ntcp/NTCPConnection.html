    Closeable, AutoCloseable
    public class NTCPConnectionextends Object implements Closeable
    Coordinates a connection to a single peer using NTCP 1 or NTCP 2 protocols. Manages the complete connection lifecycle including establishment, message encryption/decryption, bandwidth management, and graceful shutdown.

    Public only for UI peers page. Not a public API, not for external use.

      • getEstimatedRTT

        public int getEstimatedRTT()
        Round trip time of the handshake that established this session.

        Recorded once when establishment completes, from the same now - getCreated() interval the clock-skew calculation already performs, and not refreshed for the life of the session. The session's current latency is a question for the transport's own estimator; this is the cost of getting the link up, which is what a profile's first-hop RTT is recorded as.

        Returns:
        the handshake round trip time in ms, or 0 if not yet established

      • noteEstablishmentRtt

        void noteEstablishmentRtt(int rttMs)
        Record the handshake round trip time, once the establishment completes.

        First writer wins. Both establishment directions converge here, so whichever observes VERIFIED first supplies the sample and a late second observation cannot overwrite it - the value has exactly one source per session, and re-deriving it later would make the same session's latency depend on read timing.

        Parameters:
        rttMs - measured round trip time in ms; values of 0 or less are ignored

      • shouldRecordEstablishmentRtt

        static boolean shouldRecordEstablishmentRtt(int existingRttMs, long candidateRttMs)
        Whether a candidate handshake timing should become this session's recorded latency.

        Extracted as a pure predicate so the rule is testable without a router context and a live socket. Two rejections, both about not inventing a measurement: a non-positive interval means the clock did not advance, and an already-recorded value means this session's latency already has a source.

        Parameters:
        existingRttMs - the value already recorded, 0 if none
        candidateRttMs - the newly measured interval
        Returns:
        true if the candidate should be recorded
