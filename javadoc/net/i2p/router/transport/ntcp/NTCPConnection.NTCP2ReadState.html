      • allocReadBuf

        private ByteArray allocReadBuf(int framelen)
        Allocate the scratch buffer for the announced frame on the buffered (split-frame) read path.

        A pooled 16 KB buffer is used for regular frames; oversized frames get a one-off allocation since the pool only holds the fixed 16 KB class and a pooled buffer would be too small. A previous pooled buffer that is too small is returned to the pool first so the bounded pool is not drained by repeated large frames.

        Parameters:
        framelen - the announced frame length
        Returns:
        a fresh buffer for the frame; never null

      • decryptAndProcess

        private boolean decryptAndProcess(byte[] data, int off)
        Decrypts in place. Length is _framelen Side effects: Sets _received = -2, increments _frameCount and _blockCount if valid, calls destroy() and sets _terminated if termination block received or if invalid.

        Does not call close() on failure. Caller MUST call NTCPConnection.delayedClose(ByteBuffer, int) if this returns false.

        Parameters:
        data - the buffer holding the packet
        off - the offset of the packet in the buffer
        Returns:
        success, false for fatal error (AEAD) only

      • processFrameBlocks

        private void processFrameBlocks(byte[] data, int off)
        Process the decrypted payload of the current frame, delivering each block to the PayloadCallback. Payload errors are logged but never escalate to a connection close; only AEAD failures (handled by the caller before this point) are fatal.
        Parameters:
        data - the buffer holding the decrypted frame
        off - the offset of the frame in the buffer
