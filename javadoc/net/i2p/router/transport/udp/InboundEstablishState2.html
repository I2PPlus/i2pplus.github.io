    Data for a new connection being established, where the remote peer has initiated the connection with us. In other words, they are Alice and we are Bob.

    SSU2 only.

      • selectSessionAddress

        static InboundEstablishState2.AddressSelection selectSessionAddress(List<RouterAddress> addrs, boolean isIPv6, byte[] aliceIP)
        Choose the RouterInfo address this session negotiates with, given the sender's IP family, so the caller can determine the MTU and keys. The rules mirror the SSU2 handshake:
        • with several addresses, a pure SSU 1 address (no "s" option) is skipped
        • an address is skipped when its host is not compatible with the sender's IP family, unless the capacity bit marks it usable
        • an address is skipped when it advertises the sender's own IP (yggdrasil addresses and a matching IPv6 source prefix cannot be ourselves)
        • an address that advertises a different IP than the sender's source address is selected but flagged, so the caller can ban it after the signature is verified
        Parameters:
        addrs - the addresses from the peer's RouterInfo, in preference order
        isIPv6 - true if the sender connected over IPv6
        aliceIP - the sender's source IP bytes (4 for IPv4, 16 for IPv6)
        Returns:
        the selection; ra is null when no address qualified

      • parseMTU

        static int parseMTU(RouterAddress ra, boolean isIPv6) throws InboundEstablishState2.RIException
        Resolve the session MTU from the peer's "mtu" option. Pure decision logic: a missing or unparsable value falls back to the per-style/family default, the 1.9.0 workaround maps 1276 to MIN_MTU for SSU 1, and any other value is clamped into the legal range for the negotiated style and IP family. A declared MTU below MIN_MTU (other than the workaround) is rejected.
        Parameters:
        ra - the negotiated SSU2/SSU address
        isIPv6 - true for an IPv6 session
        Returns:
        the effective MTU
        Throws:
        InboundEstablishState2.RIException - with REASON_OPTIONS if a declared MTU is below MIN_MTU

      • decideIntroduction

        static int decideIntroduction(String version, String caps, boolean sentPortOk, boolean canIntroduce, boolean randomKeep)
        Decide whether a deferred relay-tag request survives once the peer's RouterInfo is known. Pure decision logic so the branch table is testable:
        • we cannot relay while our sent port is a temporary one or the transport does not support introduction on the peer's IP family
        • we do not relay to routers running older than MIN_RELAY_VERSION
        • when the peer already advertises itself reachable we only relay on a 1-in-4 draw - the peer is likely starting up and simply unaware of its reachability
        Parameters:
        version - the peer's RouterInfo version string
        caps - the peer's RouterInfo capabilities, or null
        sentPortOk - true if our sent port is a real, stable port (at least 1024)
        canIntroduce - true if the transport can introduce on the peer's IP family
        randomKeep - the pre-rolled 1-in-4 opportunistic keep draw
        Returns:
