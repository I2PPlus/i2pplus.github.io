    Reverse-DNS resolver and cache for the comm system.

    Owns all reverse-DNS state that previously lived in CommSystemFacadeImpl: the size-limited in-memory IP-to-hostname cache with persistent file backup, the background lookup executor used by the non-blocking getCanonicalHostName(String) and getLocalHostName(String) lookups, and the periodic cache file writer. The facade retains thin delegation stubs so external callers are unaffected.

    The cache is backed by a disk file that is safely read and written using the writer's own snapshot, so a crash mid-write cannot corrupt existing entries. Entries expire in memory after EXPIRE_TIME and are evicted from disk if older than EVICT_THRESHOLD. Cache size is bounded by memory-based limits (see maxCacheSize(boolean, boolean)) with automatic eviction of expired and then oldest entries.

    Supports migration from older cache file formats missing timestamps.

      • expireHours

        static int expireHours(boolean has512MB, boolean has1GB)
        RDNS cache entry lifetime in hours, based on available memory.

        Routers with less than 512 MB keep entries for 24 h; routers with at least 1 GB keep them for 48 h; everything else for 36 h. This bounds how stale a cached hostname may be before it is re-resolved, trading freshness against load on small memory-constrained routers.

        Parameters:
        has512MB - true if the router has at least 512 MB of max memory
        has1GB - true if the router has at least 1 GB of max memory
        Returns:
        entry lifetime in hours (24, 36, or 48)

      • accelerateEviction

        static boolean accelerateEviction(int size, int maxSize)
        Whether a full cache should evict entries at an accelerated rate.

        When the cache exceeds 90% of its maximum size, the TTL applied by entryExpired(long, long, boolean) is halved so eviction keeps up with insertion load. Choosing the threshold as a percentage of the max (not an absolute number) keeps behavior consistent across the memory-dependent cache sizes.

        Parameters:

        maxSize - maximum cache entry count
        Returns:
        true if the cache is more than 90% full

      • needRdnscacheSweep

        static boolean needRdnscacheSweep(int size, int maxSize, int counter)
        Decide whether a cache insert must run a full-cache cleanup sweep. See needRdnscacheSweep(int, int, int) for the amortization rule.

        Sweeping on every put when the cache sits at its cap is O(n) per insert and shows up as CHM iterator churn on the rDNS hot path. Instead the sweep is amortized: once the map is at/over its cap it runs at most once every CLEANUP_BITS inserts (it usually stays pegged at the cap in steady state), while exceeding the cap by more than MAX_SLACK entries still sweeps immediately so the memory bound stays hard.

        A benign race on the shared _rdnsCleanupCounter only changes which insert triggers the sweep; it never under-sweeps below the slack guard (the size check is made against the live map by the caller).

        Parameters:
        size - current cache size; use rdnsCache.size()
        maxSize - the cache cap, e.g. MAX_RDNS_CACHE_SIZE
        counter - a per-put counter, e.g. an incrementing static int
        Returns:
        true if a cleanup sweep must run before the insert
