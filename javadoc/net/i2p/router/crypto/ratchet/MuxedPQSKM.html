      • preferRatchetNow

        boolean preferRatchetNow()
        The ordering the current window favours, without rolling the sampling window over. Reporting has to use this rather than preferRatchet(): a log line that resets the counters changes which decrypt the next message tries first, and the value it prints is not the one that decision used.
        Returns:
        true if the Ratchet decrypt would be tried first right now

      • preferRatchet

        static boolean preferRatchet(int ec, int pq)
        The ordering the current window favours, with the PQ count discounted because the ratchet slow decrypt is the cheaper of the two to try first.
        Parameters:

      • rollOver

        static boolean rollOver(AtomicInteger counter, int expected)
        Reset one counter to start a fresh window, only if nothing was recorded since the value the decision was taken on. A plain set(0) would discard any success logged between that read and the reset, which is how the counters used to lose counts under concurrent decrypts.
        Parameters:
        counter - the counter to roll over
        expected - the value read when the decision was taken
        Returns:
        true if the counter was reset, false if it moved in the meantime
