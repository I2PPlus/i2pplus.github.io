    class RatchetTagSetextends Object implements TagSetHandle
    Manages session tags and keys for a single ratchet direction with automatic key generation, supporting both inbound lookahead and on-demand outbound operations

    For outbound, uses very little memory. Tags and keys are generated on demand. See proposal 144.

    For inbound, generates tags in advance, maintaining minSize lookahead. Keys are generated as required.

    Caller must synch on all methods.

      • _registeredTags

        private final Set<RatchetSessionTag> _registeredTags
        Tags registered in the SKM's _inboundTagSets map. Used for O(tags_in_set) removal in RatchetSKM.consumeTag(SessionTag) instead of O(total_tags) scan of the entire _inboundTagSets map. Only populated for inbound tagsets (where _lsnr != null). Pruned as the ratchet advances and when the handshake finishes, so it tracks the live window instead of every tag the session ever generated.

      • _tagNumbers

        private final Map<RatchetSessionTag, Integer> _tagNumbers
        What each tag in _sessionTags is numbered by, so consume() can find a presented tag in constant time. Without it every inbound ES message scans the whole receive window comparing tags - up to 320 equals() calls per message. Maintained alongside _sessionTags: every append, removal and clear does both, so a tag in one is in the other.

      • getExpiration

        public long getExpiration()
        For inbound and outbound: Expiration. Expiration is getDate() + getTimeout() if acked. Before acked, uses _created + _timeout (full lifetime).

        Previously this used Math.min(int, int)_timeout, SESSION_PENDING_DURATION_MS) which capped unacked ES tagsets at 3 minutes instead of their designed 10-minute SESSION_LIFETIME_MAX_MS. With i2cp.disableLoopback=true, the NSR round-trip through the full tunnel path could exceed 3 minutes, causing tags to expire before the first ES message arrived.

        NSR tagsets are unaffected — they have _timeout = SESSION_PENDING_DURATION_MS (3 min), so the min() was a no-op for them.

        Returns:
        the expiration time
