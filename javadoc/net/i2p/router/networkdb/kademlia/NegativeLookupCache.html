    Negative cache for network database lookup operations.

    Caches failed lookup attempts to prevent repeated queries to unavailable or malicious peers. Uses per-entry TTL with backoff instead of a wholesale counter wipe: a key that trips the threshold stays cached for entryTtl(tripGeneration) from its last fail, and re-trips extend that hold up to ENTRY_TTL_MAX_MS. Clearing all keys on a timer synchronized re-probe storms across every recently-failed destination at once.

    Partial (below-threshold) fail streaks still expire after netdb.negativeCache.cleanupInterval so the historical contract "N fails within the cleaner window" is preserved per key, without resetting unrelated keys.

    Thread-safe implementation with atomic counters and scheduled cleanup operations for reliable concurrent access in multi-threaded environments.
