    Base class for tunable params with history tracking and auto-revert.

    Each param wraps a single router configuration value. The tuning loop reads an observed stat, computes a target, and applies it:

    observed = getObservedStat()
target   = computeTarget(observed)
target   = clamp(target, min, max)
target   = dampenByHealth(target, current)
target   = accelerateRollback(target, current, defaultValue)
applyValue(target)

    Min/max/step ranges are stored in autotune.config and can be changed at runtime via the console UI (no restart needed). Factory defaults are captured on first run and persisted for auto-revert when system health is degraded.

    Thread safety: all fields are accessed only from the Tuner timer thread, except _override and _autoTuning which are set from the console form handler.

      • refreshDefault

        public void refreshDefault(RouterContext ctx)
        Re-read the default value from autotune.config for live updates.

        Called once per tuning cycle. When a user saves a new default via the console form, this method picks it up and uses it as the auto-revert target. If the persisted default differs from the factory default (code-level default), it is treated as stale and ignored. The factory default is the authoritative source of truth.

        A stale default is a persistent config state, not a recurring event: it stays in autotune.config until edited, so re-announcing it every cycle produced thousands of identical WARN lines for a condition the code already handles correctly. It is therefore reported once per param at DEBUG, and WARN stays free for things that actually need attention.

        Parameters:
        ctx - router context, unused here; kept for symmetry with refreshRanges

      • getObservedStat

        protected abstract double getObservedStat(RouterContext ctx)
        Observed stat value used for autotuning.

        ctx is always this param's own context: Tuner takes a single RouterContext, hands the same instance to every BaseParam constructor, and both call sites pass _ctx. It was previously passed as null, which silently broke any implementation that used the argument instead of the field — a param reading a cross-reference stat then threw on every tuning cycle, was caught by the cycle handler, and never tuned at all, with nothing but a repeated WARN to show for it. Implementations may use either ctx or _ctx; both are the same object.

        Parameters:
        ctx - router context, never null
        Returns:
        observed stat value for autotuning

      • getStatPeriodStamp

        protected double getStatPeriodStamp(RouterContext ctx, String statName)
        When the window behind a stat's event count last completed, in ms, or NaN when it cannot be determined.

        A coalesced Rate stamps the wall clock of every coalesce, and coalescing is what closes a period, so this advances exactly once per window. It is the identity of the window, which is what a caller needs to tell "a new reading exists" from "the same reading as last cycle".

        The event count itself cannot serve: two periods can carry identical counts, an idle period repeats (0, 0) forever, and a count of zero means the ratio is undefined rather than low. Any of those reads as "unchanged" and freezes a decision that depends on it.

        Parameters:
        ctx - the router context
        statName - the stat to query
        Returns:
        the last coalesce time in ms, or NaN

      • update

        public void update()
        Main tuning loop for this param. Called each tune cycle: every 5s for transport thread pool params, every 15s for all others.

        Sequence:

        1. Read observed stat via getObservedStat(RouterContext)
        2. Record value/stat history for sparklines
        3. Skip if auto-tuning disabled or stat unavailable
        4. Auto-revert to default if system health < 0.3
        5. Compute target via computeTarget(double)
        6. Apply health-based dampening (reduces step when degraded)
        7. Clamp to [min, max]
        8. Accelerate rollback when param diverges from default
        9. Call applyValue(int) and persistValue(RouterContext, int)
        Specified by:
        update in interface Tuner.TunableParam
