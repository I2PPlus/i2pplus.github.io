      • addedOn

        public long addedOn
        When this ban was first recorded, per the i2p clock; 0 when unknown.

        Separate from expireOn because the ban duration varies by class and by transport, so the start time cannot be derived from the expiry. Needed to answer "was this peer already banned when the build was dispatched, or did the ban land mid-flight" — the two need different fixes, and only the duration was previously observable.

        On a re-ban that keeps the older, longer expiry this retains the original start time: what matters is how long the banlist has been holding this peer, not when the latest report arrived.
