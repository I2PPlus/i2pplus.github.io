    class PumpedTunnelGatewayextends TunnelGateway
    This class represents a tunnel gateway with multiple hops that accepts messages, then coalesces and fragments them before sending them down the tunnel.

    The processing flow is:

    1. add an I2NPMessage (and optionally, the target router or tunnel)
    2. messages queue in this PumpedTunnelGateway's internal _prequeue
    3. QueuePreprocessor pulls PendingGatewayMessages from _prequeue and processes them
    4. Fragments are sent to Sender, encrypted, and delivered to the Receiver
    5. Receiver directs the message to the next tunnel hop or endpoint

    This class uses specialized CoDel queues to manage queue delays and bufferbloat. The outbound gateway uses a priority queue, while inbound uses a bounded non-priority queue.

    Thread safety:

    • _prequeue is a thread-safe blocking queue managing pending messages
    • _queue is synchronized for modifications and preprocessing
    • Expiration pruning is done outside locks to minimize contention
    • The pump(List) method is safe for concurrent invocation by pumper threads

        Gateway queue depths observed since the last flush, reported as one mean sample per pump rather than one sample per message. The stat is a level the Tuner and the graphs read as a per-period average, so the mean is the same quantity; sampling it per message cost a stat lookup and one monitor per rate period for every message enqueued, which on a busy gateway is thousands a second.

      • pump

        public boolean pump(List<PendingGatewayMessage> queueBuf)
        Pumps messages from the internal prequeue into the processing queue.

        This method tries to drain a bounded number of messages from _prequeue into the provided queueBuf, then adds them to the internal _queue for preprocessing and fragmentation.

        Expired messages are removed after preprocessing, outside the synchronization block, to reduce contention.

        Parameters:
        queueBuf - an empty list used as a temporary buffer for messages (will be cleared before return)
        Returns:
        true if there are still messages remaining in _prequeue and the caller should requeue this gateway
