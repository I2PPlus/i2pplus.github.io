    Temporarily excludes unresponsive peers from tunnel build selection.

    A peer is excluded only after i2p.tunnel.ghostPeer.timeoutThreshold consecutive timeouts (strikes); earlier timeouts are tracked but do not exclude the peer on their own.

    The exclusion is flat and short — DEFAULT_COOLDOWN_MS, with no escalation for repeat timeouts.

    Escalation was removed because it bought nothing. The cooldown this mark governs is not the one that keeps a failed peer out of selection: TunnelPeerSelector.FIRST_HOP_FAIL_COOLDOWN_MS is five minutes, and ProfileOrganizer.passesBasicGates tests it directly, so a peer that failed as a first hop is already excluded from tier promotion for five minutes regardless. Every ghost cooldown the router can express — 120s, 300s, or the 240s an escalation produced — sat inside that window. Doubling it on a repeat timeout therefore excluded the peer from more than it already was, while making the mark outlive the build burst it was written to cover, which is the only thing it is uniquely positioned to do: the mark also gates promotion in roles the first-hop cooldown does not cover, and a recovered peer should be back in those roles within a minute or two.

    What a silently dead peer is protected by is eviction, not escalation. BuildExecutor.penalizeTimeout demotes the contacted hop from the fast and high-cap tiers on the same failure, and the three-strike demoteIfUnreachable still runs for the failures that do not indict the peer. A peer that is dead leaves the candidate set on evidence, not on a timer.

    Tracked marks are hard-bounded at MAX_TRACKED_PEERS (expired marks evicted first, then those nearest to expiry), and the *active* exclusion set is separately hard-bounded at MAX_ACTIVE_GHOSTS by deactivating the exclusions closest to lapsing. Without that second bound a burst of timeouts can exclude enough of the reachable set that tier selection returns no candidates at all — the exclusion list starves the very selection it is meant to protect. Deactivation keeps offenses and markedAt, so the strike history survives and a peer that times out again still counts toward timeoutThreshold.

    The active exclusion count is cached so getGhostCount() is a volatile read on the hot path instead of a full map scan; its sweep deadline is bucketed to COUNT_GRANULARITY_MS so scattered expiry times cost at most one rescan per bucket rather than one per mark.

      • OFFENSE_DECAY_MS

        static final long OFFENSE_DECAY_MS
        Window in which repeat timeouts keep counting toward i2p.tunnel.ghostPeer.timeoutThreshold. After this long without a fresh timeout the strike count resets, so a peer that recovered and later has one bad day starts the count over rather than being excluded on its first strike.

        This no longer governs a cooldown — the exclusion is flat (DEFAULT_COOLDOWN_MS) — but it still governs whether a timeout is a first strike or a repeat one when the threshold is above 1.

      • COUNT_GRANULARITY_MS

        static final long COUNT_GRANULARITY_MS
        Sweep deadlines are rounded up to this many milliseconds.       • BY_EXPIRY

        private static final Comparator<Map.Entry<Hash, GhostPeerManager.GhostMark>> BY_EXPIRY
        Eviction order by expiry ascending: expired marks sort first (oldest expiry first, so they go in the order they lapsed), followed by active marks nearest to lapsing.       • recordTimeout

        public void recordTimeout(Hash peer)
        Record that a peer timed out during tunnel build.

        The peer is excluded only once its strike count reaches the configured threshold (i2p.tunnel.ghostPeer.timeoutThreshold, at least 1). Earlier strikes are recorded without excluding it, so the configured sensitivity actually gates selection. The exclusion expiry is snapshotted at mark time so a later state change doesn't extend or shorten an active exclusion; a fresh timeout is new evidence and re-marks the peer for a fresh DEFAULT_COOLDOWN_MS. Re-marking also repairs the old stale-entry hole where an expired, never-pruned entry made putIfAbsent silently no-op and left the peer unmarked.

        Parameters:
        peer - the router hash of the peer that timed out; our own hash is ignored

        private void adjustActiveLocked(boolean wasActive, boolean isActive, long until)

      • capActiveLocked

        private void capActiveLocked(long now)
        Enforce MAX_ACTIVE_GHOSTS: a burst of timeouts that excludes enough of the reachable set makes tier selection return nothing. The exclusion intended to protect the build instead starves it (seen as "All selected peers were ghosts"). Deactivate the excess, dropping the exclusions nearest to lapsing so the set keeps the marks with the most time left. Deactivation zeroes until only: the offense count and mark time survive, so a peer that keeps timing out re-escalates instead of starting over. No-op — and so free — while the set is within bounds. Caller must hold this.
        Parameters:
        now - current router time (ms)

      • pruneToLimitLocked

        private void pruneToLimitLocked(long now)
        Enforce MAX_TRACKED_PEERS as a hard bound. Triggered only once the bound is actually reached, then evicted down to the headroom, so the headroom really is the number of inserts absorbed before the next pass rather than the point the pass starts at. Eviction order is BY_EXPIRY — expired marks first, then actives nearest to lapsing. O(n log n), once per headroom's worth of inserts. Rescans the active count only when it actually evicted, so the caller's single delta isn't undone by an unconditional recompute. Caller must hold this.
        Parameters:
        now - current router time (ms)

      • recordSuccess

        public void recordSuccess(Hash peer)
        Record successful tunnel participation by a peer. Clears ghost status immediately, including its offense history. A peer that just routed a tunnel is proven live.

        Called for every peer on every successful build, so the overwhelming majority of calls find no mark present. Only a call that actually removed a mark is counted: a success from a peer that was never excluded is not a recovery, and counting those inflated this stat to roughly 3.4x the number of marks added, which made the two counters impossible to reconcile.

        Parameters:
        peer - the router hash of the peer that just routed a tunnel; our own hash is ignored

      • getFastOrHighCapGhostCount

        public int getFastOrHighCapGhostCount()
        Count of active ghost exclusions whose peer sits in the fast or high-capacity tier, a peer in both tiers counted once.

        Needed to pair with ProfileOrganizer.getFastOrHighCapCount(): an all-tier ghost count divided by a tier size overstates, because most marks land on peers that were never in the preferred tier and would not have competed for those slots.
