    class ClientPeerSelectorextends TunnelPeerSelector
    Pick peers randomly out of the fast pool, and put them into tunnels ordered by XOR distance from a random key.

      • logAcceptedFirstHopTier

        private void logAcceptedFirstHopTier(RouterContext ctx, Hash firstHop, int tier, int attempt, int attempts, int remaining, double buildSuccess)
        Log the quality tier that actually produced this build's first hop.

        The first-hop quality ladder relaxes its reachability requirement as attempts accumulate: tiers 0 and 1 require the peer to be established or connecting, tier 2 requires neither. A gateway taken at tier 2 is therefore one we have no transport session with, and cannot receive a build request — which is indistinguishable, from the outside, from a peer that went silent. This line is the only way to tell those apart after the fact.

        Rate limited to one line per TIER_LOG_INTERVAL_MS per tier so a busy build loop cannot turn the diagnosis into the noise it is meant to explain; the counters accumulate regardless and are reported in the same line. The limiter uses compute rather than replace(k, old, new): replace is a no-op returning false when the key is absent, so the first log for each tier would never happen and the key would never be inserted.

        Parameters:
        ctx - the router context
        firstHop - the accepted gateway, or null if none was accepted
        tier - the tier it was accepted at, or -1
        attempt - the attempt number it was accepted on, or -1
        attempts - total quality attempts made
        remaining - candidates left in the set
        buildSuccess - the tunnel build success ratio, reported in the log line
