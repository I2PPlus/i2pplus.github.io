    Service
    public class TunnelDispatcherextends Object implements Service
    Handle the actual processing and forwarding of messages through the various tunnels.
    For each type of tunnel, it creates a chain of handlers, as follows:

Following tunnels are created by us:

    Outbound Gateway > 0 hops:
      PumpedTunnelGateway
        BatchedRouterPreprocessor -> OutboundSender -> OutboundReceiver -> OutNetMessagePool

    Outbound zero-hop Gateway+Endpoint:
      TunnelGatewayZeroHop
        OutboundMessageDistributor -> OutNetMessagePool

    Inbound Endpoint > 0 hops:
      TunnelParticipant
       FragmentHandler ->  InboundEndpointProcessor -> InboundMessageDistributor -> InNetMessagePool

    Inbound zero-hop Gateway+Endpoint:
      TunnelGatewayZeroHop
        InboundMessageDistributor -> InNetMessagePool


Following tunnels are NOT created by us:

    Participant (not gateway or endpoint)
      TunnelParticipant
        HopProcessor -> OutNetMessagePool

    Outbound Endpoint > 0 hops:
      OutboundTunnelEndpoint
        FragmentHandler -> HopProcessor -> OutboundMessageDistributor -> OutNetMessagePool

    Inbound Gateway > 0 hops:
      ThrottledPumpedTunnelGateway
        BatchedRouterPreprocessor -> InboundSender -> InboundGatewayReceiver -> OutNetMessagePool

      • shouldDropParticipatingMessage

        boolean shouldDropParticipatingMessage(TunnelDispatcher.Location loc, int type, int length, SyntheticREDQueue bwe)
        Implement RED (Random Early Discard) to enforce bandwidth limits. Only active when queue size > minThreshold (congestion). When queue > maxThreshold, ALL messages are dropped (regardless of factor).
        Parameters:
        loc - role of the sender in the tunnel, used for logging only
        type - message type, used for logging only
        length - message size in bytes; 0 or less is never dropped
        bwe - per-tunnel estimator consulted before the global limit, may be null to skip the per-tunnel check
        Returns:
        true to drop, false to accept

      • shouldDropParticipatingInboundMessage

        boolean shouldDropParticipatingInboundMessage(TunnelDispatcher.Location loc, int type, int length, SyntheticREDQueue bwe)
        Check if we should drop an inbound participating tunnel message. Implements symmetric throttling: both inbound and outbound transit traffic should be throttled equally to prevent inbound traffic from overwhelming outbound capacity.
        Parameters:
        loc - location in tunnel (IBGP, PARTICIPANT, OBEP)
        type - I2NP message type, reported in the drop log only
        length - message size in bytes
        bwe - per-tunnel bandwidth estimator (may be null)
        Returns:
        true to drop, false to accept

      • getMaxPerTunnelBandwidth

        int getMaxPerTunnelBandwidth(TunnelDispatcher.Location loc)
        The max bandwidth per transit tunnel. Scales with allocation: higher share = higher per-tunnel cap. Uses outbound bandwidth only. On floodfill routers inbound is far smaller than outbound and would create an artificial bottleneck.
        Parameters:
        loc - role in the tunnel, currently unused; the cap depends only on the outbound rate and our share percentage
        Returns:
        cap in bytes per second, floored at 10KB (30KB or 50KB for the larger allocation tiers) once the computed value exceeds 256KB
