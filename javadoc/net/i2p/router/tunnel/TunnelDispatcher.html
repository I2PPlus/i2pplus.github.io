    Service
    public class TunnelDispatcherextends Object implements Service
    Handle the actual processing and forwarding of messages through the various tunnels.
    For each type of tunnel, it creates a chain of handlers, as follows:

Following tunnels are created by us:

    Outbound Gateway > 0 hops:
      PumpedTunnelGateway
        BatchedRouterPreprocessor -> OutboundSender -> OutboundReceiver -> OutNetMessagePool

    Outbound zero-hop Gateway+Endpoint:
      TunnelGatewayZeroHop
        OutboundMessageDistributor -> OutNetMessagePool

    Inbound Endpoint > 0 hops:
      TunnelParticipant
       FragmentHandler ->  InboundEndpointProcessor -> InboundMessageDistributor -> InNetMessagePool

    Inbound zero-hop Gateway+Endpoint:
      TunnelGatewayZeroHop
        InboundMessageDistributor -> InNetMessagePool


Following tunnels are NOT created by us:

    Participant (not gateway or endpoint)
      TunnelParticipant
        HopProcessor -> OutNetMessagePool

    Outbound Endpoint > 0 hops:
      OutboundTunnelEndpoint
        FragmentHandler -> HopProcessor -> OutboundMessageDistributor -> OutNetMessagePool

    Inbound Gateway > 0 hops:
      ThrottledPumpedTunnelGateway
        BatchedRouterPreprocessor -> InboundSender -> InboundGatewayReceiver -> OutNetMessagePool

      • _dispatchParticipantStat

        private final RateStat _dispatchParticipantStat
        Cached handles for the three per-transit-message counters reported by dispatch(TunnelDataMessage, Hash) and dispatch(TunnelGatewayMessage).

        These cannot be batched: N calls of addRateData(name, 1) give a period total of N and an event count of N, and both are read — GraphListener stores the count when total equals count, and the Tuner reads Rate.getLastEventCount() directly. Batching would keep the plotted value right and drop the count to one per flush.

        What they do not need is the string-keyed map lookup and log-level check on every call. Resolved after initializeStats() so the handles can only ever alias an already-registered stat.

        Returns:

      • expiredConfigs

        static List<HopConfig> expiredConfigs(Collection<HopConfig> configs, long now)
        The queued configs whose expiration, plus the expiry fudge, has already passed.

        The whole queue is scanned. It is filled in join order, so an entry that is still live can sit in front of entries that expired long ago; stopping at the first live entry left those behind, holding a tunnel ID and transit bandwidth until the head itself expired.

        Parameters:
        configs - the queued participating tunnels
        now - current time, already allowing for the clock fudge
        Returns:
        the expired configs, in queue order; an empty list if none
