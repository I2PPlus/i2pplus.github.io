    java.lang.Object
    net.i2p.router.Banlist
    public class Banlistextends Object
    Manages router banlist entries with configurable expiration times and transport-specific bans. Provides methods to add, remove, and query ban status for routers based on various criteria including permanent bans, temporary bans, and transport-specific restrictions.

      • BANLIST_FOREVER_THRESHOLD

        private static final long BANLIST_FOREVER_THRESHOLD
        A ban that expires after this will return true in isBanlistedForever(Hash). In the transports, "forever" is treated as a hard ban, and both inbound and outbound connections will be rejected. Not-forever is treated as a soft ban, with outbound rejected but inbound will be allowed and will automatically unban.
        See Also:

      • MAX_VALID_VERSION

        static final String MAX_VALID_VERSION
        Highest I2P version recognised as real. No released version reaches it, so a RouterInfo publishing a version at or above this ceiling has built the RouterInfo by hand - usually a scanner probing for netdb storage. Kept here so the NTCP2 handshake, the floodfill store path and the data store all agree on one ceiling.

      • shouldBanlistByCapability

        public String shouldBanlistByCapability(String capabilities)
        Check if router capabilities match any of the custom ban patterns.

        A pattern may carry an exclusion group after '!': "G!f" matches routers with G in their caps unless they are also floodfills. Exclusions require at least one required character.

        Comparison is case-sensitive throughout: capability letters are case-significant (lowercase 'f' is floodfill, uppercase letters are separate meanings), so neither the stored patterns nor the router's caps may be case-folded before matching.

        Parameters:
        capabilities - router capabilities string (e.g., "XfP")
        Returns:
        the matched pattern exactly as configured (e.g., "G!f") or null if no match

      • matchCapabilityPattern

        static String matchCapabilityPattern(String capabilities, String patternsStr)
        Pure decision helper: match a capabilities string against a comma/space-separated list of capability ban patterns.

        Each pattern is a set of required characters, optionally followed by '!'. A router matches when it carries every required character and none of the excluded ones. A pattern with an empty required part can never match, so a bare exclusion cannot ban the entire network. Case-sensitive: see shouldBanlistByCapability(String).

        Parameters:
        capabilities - router capabilities string, may be null
        patternsStr - configured patterns, may be null or empty
        Returns:
        the first matching pattern as configured, or null if none match

      • getBanAge

        public long getBanAge(Hash peer)
        How long the banlist has been holding a peer, in milliseconds.

        This is the discriminator between the two reasons a build request arrives naming a banlisted peer, which need different fixes:

        • old age — the ban predates the build, so peer selection handed out a peer the banlist already held, which is a selection bug;
        • young age — the ban landed while the build was in flight, so the selection was correct and only a selection-time cooldown would stop the next request repeating it.
        The ban duration class cannot substitute: a peer permanently banned mid-flight and one banned last week both report as permanent.
        Parameters:
        peer - the router hash to check
        Returns:
        age of the standing ban in ms, or -1 if the peer is not currently banlisted or the entry predates this field

      • getBanCause

        public String getBanCause(Hash peer)
        Reason recorded when the peer was banlisted.

        Diagnostic only. A rejected tunnel build says a peer was banned but not why, so a burst of rejections cannot be attributed to a cause. Without it the only way to find out which subsystem is banning peers is to add temporary logging to each caller.

        Parameters:
        peer - the router hash to check
        Returns:
        the recorded cause code or reason, or null when the peer is not currently banlisted or no cause was recorded
