      • axisFloor

        static double axisFloor(double dataMin, double dataMax, boolean forceZero)
        Choose the y-axis floor for a window, so a series that lives in a narrow band far from zero is not flattened against a zero baseline.

        Only the floor is ever returned. The ceiling and the tick rounding are left to rrd4j, which snaps the floor down to cover any value that does not fit and otherwise rounds both ends to its own idea of a sensible label value.

        Pure, so the decision can be unit tested without a router, an RRD or a clock.

        Parameters:
        dataMin - smallest finite value in the window, NaN if none
        dataMax - largest finite value in the window, NaN if none
        forceZero - true to keep the historical zero-floored axis
        Returns:
        the floor to pass to RrdGraphDef.setMinValue

      • isCondensedTile

        static boolean isCondensedTile(GraphRenderer.GraphRenderConfig cfg)
        Whether a tile is narrow and carrying condensed data, and so takes the theme's condensed plot width.

        Separate from isCrowdedTile(GraphRenderer.GraphRenderConfig) because the two answer different questions. A crowded tile has enough periods that any width merges the series, so it takes a fixed hairline. A condensed tile is merely narrow for the number of periods it carries, so the weight stays the theme's to set - thinner than an ordinary plot, but not a hairline.

        Deliberately independent of smoothing. Smoothing used to exempt a tile from this, because an unsmoothed polyline crowds where a rounded curve does not - but smoothing is itself only a default, and a stepped series is what a user asking for step gets. Gating on it meant the same tile was drawn at two different weights depending on a setting whose value nobody reading the graph could see.

        Parameters:
        cfg - the render configuration
        Returns:
        true if a narrow, period-dense tile takes the theme's condensed plot width

      • extraSeriesColor

        static Color extraSeriesColor(String theme, boolean allLines, int extraIndex)
        The colour for an extra series: plot ordinal 1, i.e. the theme's second hue.

        A frame carries at most two plots (GraphGroups.MAX_SERIES), so "which colour is the extra series" has exactly one answer and it is a themeable one. The two-series bandwidth graph predates grouping and keeps the exact colour it always shipped with.

        Parameters:
        theme - console theme name
        allLines - whether the primary is drawn as a line rather than a filled area
        extraIndex - zero-based position among the extra series
        Returns:
        the colour for that series

      • extraLineShadeForTest

        static Color[] extraLineShadeForTest(String theme, int extraIndex)
        The value-shade stops an extra series would be drawn with.

        Exposed so a test can check that the extra series asks for its own plot's stops rather than a neighbouring plot's. Comparing colours could not catch that, because every shipped theme draws both plots flat and a flat plot has no stops to compare.
