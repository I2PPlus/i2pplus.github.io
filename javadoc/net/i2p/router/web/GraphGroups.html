    net.i2p.router.web.GraphGroups
    public final class GraphGroupsextends Object
    Registry of graph groupings: sets of stats that answer the same question and share a unit, so they can be drawn as one multi-series plot instead of several small ones.

    Every member of a group is either a count or a duration or a rate, and the members of one group always agree on which. That constraint is the whole point. Combining stats whose units differ produces a plot that looks meaningful and is not: a count against a byte count, or a per-second rate against a total, flattens the smaller series into the baseline and reads as "nothing happening". Members were therefore checked against their declaring code rather than their names.

    Grouping is opt-in via PROP_COMBINE and only takes effect where at least two members are already enabled, so enabling a single stat of a group is never silently changed into a combined plot.

      • MAX_SERIES

        public static final int MAX_SERIES
        Most series drawn on one plot.

        Every group is now at or under MAX_SERIES: no frame combines more than two, because a tile is too small to read a third line and two hues are all the palette needs. This stays as a hard cap so a group added later cannot silently exceed it, and GraphGroupsTest asserts the current groups all comply.

      • pairGroupIds

        public static Set<String> pairGroupIds(Set<String> enabledStats)
        The In/Out pairs the enabled stats form.

        Only pairs the user has switched on both halves of are returned: a group id for a half-enabled pair would render as an empty tile, and pairing must never turn a single enabled stat into a combined plot. Stats the registry already claims are skipped, so a declared group and a generated one can never cover the same rate.

        Parameters:
        enabledStats - stat names enabled by the user, without period suffixes; null yields no pairs
        Returns:
        the pair ids, in name order; never null
