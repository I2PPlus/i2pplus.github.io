    net.i2p.router.web.helpers.GraphHelper
    public class GraphHelperextends FormHandler
    Renders the graphs list (/graphs.jsp) and the single-stat page (/graph.jsp), plus the graph display configuration form.

    Stateless across requests except for per-request form state set via the setXxx() accessors; preferences are read from context properties.

      • effectiveRefresh

        static int effectiveRefresh(int saved, boolean graphingDisabled)
        The auto-refresh delay a page render should actually use.

        Refreshing is pointless while graph generation is unavailable, and hammering a console that cannot render is worse than showing nothing, so the delay is suppressed for that one render. It is deliberately not persisted: graph generation can come back, and writing the suppression into the config made it permanent, so once graphing had been unavailable for any reason the graphs page would freeze on its first paint and never refresh again, even after the router had recovered.

        Parameters:
        saved - the configured delay in seconds
        graphingDisabled - whether graph generation is currently unavailable
        Returns:
        the delay to use for this render, or -1 to suppress refreshing

      • resolveShowEvents

        static boolean resolveShowEvents(String param, boolean current)
        Resolves the requested events mode against the mode in force.

        An absent or empty parameter means "not specified", and the mode already in force - which came from routerconsole.graphEvents - stands. It must not be read as a request for events: the enlarged-graph link only emits showEvents when events are on, so a time-mode link omits it, and the old !"false".equals(b) turned that omission into true. Opening the larger view of a time graph silently switched it to events and contradicted the configured default. The two URL-building sites disagreed about whether the parameter is always present; this makes the reader tolerant of its absence instead.

        The value is also parsed symmetrically with the way it is written. One link emits showEvents=1 and the image sources emit showEvents=true|false, but the reader recognised only the literal string "false" - so showEvents=0, a perfectly ordinary way to spell it, was read as a request for events.

        Parameters:
        param - the request parameter, may be null or empty
        current - the mode currently in force
        Returns:
        the mode to use

        Only the space was escaped before, so a tunnel nickname carrying &, +, = or % silently split or corrupted the graph link, since per-tunnel stats are named [nickname] InBps and the nickname is user input. Everything outside the unreserved set of RFC 3986 is escaped, UTF-8, uppercase hex. The name itself is never rewritten: the space that GraphGroups pairs In/Out rates on stays intact in the model and only becomes %20 on the wire, and a plain name such as bw.sendRate comes back byte-identical.

        URLEncoder is deliberately not used: it turns the space into + and rewrites characters that are already safe, which would change URLs that work today.

        Parameters:
        name - the stat or group name as registered
        Returns:
        the name safe to append to a query value
