      • MSG_REWRITES_A

        private static final String[][] MSG_REWRITES_A
        Ordered literal rewrites applied to an escaped log message, up to the double-bracket cleanup. Order is load-bearing and not mergeable: this table turns "&hellip;" into "...", which MSG_REWRITES_C turns into "…", and it ticks "false" before a later rewrite can restore "[&#10008;] positives" to "false positives".

      • MSG_REWRITES_B

        private static final String[][] MSG_REWRITES_B
        The middle of the rewrite chain, run after the double-bracket cleanup and before the newline-bullet rewrite. The un-ticking has to see the "&#10004;" and "&#10008;" that the first table produces. The last entry converts the inline " * " value separator that source log messages write for the file log into the bullet separator the console renders. The literal • is used rather than &bullet; so the rewrite cannot be broken by the HTML escaping that runs before this chain.

      • MSG_REWRITES_C

        private static final String[][] MSG_REWRITES_C
        The tail of the rewrite chain, run after the bullet rewrite. "..." has to be rewritten here, not in the first table, because it is what that table's "&hellip;" rewrite produces.

      • WRAPPER_LOG_REWRITES

        private static final String[][] WRAPPER_LOG_REWRITES
        Ordered literal rewrites applied to a raw wrapper log buffer. Order is load-bearing: "INFO | ERROR" is rewritten into "| ERROR |" first, and the later "| ERROR |" → "| ERR |" then has to see that result.

      • applyRewrites

        static String applyRewrites(String msg, String[][] rewrites)
        Apply an ordered table of literal rewrites.

        Equivalent to chaining String.replace(CharSequence, CharSequence) down the table in order, so a rewrite routinely matches text an earlier one produced. A rewrite whose needle is absent costs one indexOf and allocates nothing, which is the common case.

        Parameters:
        msg - the text to rewrite, never null
        rewrites - {needle, replacement} pairs, applied in array order
        Returns:
        the rewritten text

      • readTextFile

        private static long readTextFile(File f, boolean utf8, int maxNumLines, long skipLines, StringBuilder buf)
        Read in the last few lines of a (newline delimited) textfile, or null if the file doesn't exist.

        Same as FileUtil.readTextFile but uses platform encoding, not UTF-8, since the wrapper log cannot be configured: http://stackoverflow.com/questions/14887690/how-do-i-get-the-tanuki-wrapper-log-files-to-be-utf-8-encoded

        Warning - this inefficiently allocates a StringBuilder of size maxNumLines*80, so don't make it too big. Warning - converts \r\n to \n.

        Parameters:
        f - the file to read, -1 is returned if it does not exist
        utf8 - true for utf-8, false for system locale
        maxNumLines - max number of lines (greater than zero)
        skipLines - number of lines to skip, or zero
        buf - out parameter receiving the trailing lines, each terminated by '\n'
        Returns:
        -1 on failure, or number of lines in the file. Does not throw IOException.
