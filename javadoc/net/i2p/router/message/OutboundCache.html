    Helper cache manager for outbound message optimization in OCMOSJ.

    This class maintains several caches to optimize outbound message routing and delivery:

    • LeaseSet cache - minimizes overhead by reusing our own LeaseSet.
    • Lease cache - persists sending to the same lease to reduce out-of-order delivery.
    • Tunnel caches - caches outbound tunnels per destination to stabilize delivery paths.
    • Last reply request cache - ensures periodic replies to detect failed tunnels.
    • Multihomed cache - tracks LeaseSets for multihomed routers.

    All caches use ConcurrentHashMap with tuned initial capacity, load factor, and concurrency level to allow safe concurrent access and high throughput with low contention. Tunnel caches have been converted from HashMaps with explicit synchronization to ConcurrentHashMaps for consistent concurrency management without external locking.

    Cache cleaning occurs periodically with a configurable interval, removing expired entries to balance memory use and cache freshness.

      • pickDistinctTunnel

        static TunnelInfo pickDistinctTunnel(TunnelInfo old, List<TunnelInfo> candidates, Random rnd)
        Choose the outbound tunnel for a fresh connection, preferring a candidate different from the one used by the previous connection to the same destination. Called by OutboundClientMessageOneShotJob on the first message of a new stream (streaming SYN carrying the fresh-connection marker), so an HTTP/protocol retry does not ride the same tunnel that stalled the prior connection.

        This is pure decision logic - identity comparison only, no router context - extracted so the rotation behaviour is unit-testable.

        Parameters:
        old - the outbound tunnel used by the previous connection, or null
        candidates - pool picks gathered for this rotation, never null; may be empty when no tunnels are currently available
        rnd - randomness source for choosing among several distinct tunnels
        Returns:
        a candidate distinct from old when one exists, otherwise old unchanged, so rotation is best-effort and never blocks or drops a connection

      • shouldSkipLeaseSetSend

        static boolean shouldSkipLeaseSetSend(Long cooldownEnd, long now, Long lastValid, Long lastLookup, long transientGraceMs, long probeIntervalMs)
        Decide whether a send to a destination whose LeaseSet was not found locally should be skipped without performing a lookup.

        Failure can be confirmed or transient. A destination whose LeaseSet was valid within transientGraceMs is a transient gap: skipping must only deduplicate concurrent sends (one real probe every probeIntervalMs), never suppress the recovery search itself. A destination with no recent validity is treated as confirmed-dead and the full cooldown fast-fail applies.

        Parameters:
        cooldownEnd - end time of the fail cooldown, or null if none (epoch ms)
        now - current time in ms
        lastValid - last time a valid LeaseSet was observed, or null (epoch ms)
        lastLookup - last time a real lookup started, or null (epoch ms)
        transientGraceMs - treat as transient gap if now - lastValid <= this
        probeIntervalMs - minimum gap between real lookups for a transient gap
        Returns:
        true if the send should be skipped (dieFatal), false to probe
