    Dynamic job runner scaling controller for the JobQueue.

    Monitors queue metrics (ready job count, lag) and automatically scales the number of JobQueueRunner threads up or down based on load conditions.

    Scaling Algorithm:

    • Scale UP when: readyJobs > activeRunners * scaleUpJobsRatio OR maxLag > scaleUpLagThreshold
    • Scale DOWN when: readyJobs < activeRunners AND avgLag < scaleDownLagThreshold (sustained)
    • Bounds: min runners = max(4, cores), max runners = min(2 * router.maxJobRunners, RAM-based limit)

    Resource Saturation Gates: Scale-up is suppressed (not just limited) when the bottleneck is resource saturation rather than thread count. Emergency signals (critical lag, wedged jobs, dropped jobs) override the suppression.

    • CPU saturation: router.cpuLoad > 85%
    • GC storm: router.gcPauseTime > 50 ms/min
    • Network congestion: tunnel.buildSuccessRate < 50%
    • Bandwidth saturation: bwLimiter.outboundDelayedTime > 500ms

    Feedback Mechanism:

    • Captures pre-scale metrics before adding runners
    • Compares post-scale metrics after 2 check intervals
    • If lag, maxLag, message delay, or ready jobs INCREASED after scaling, rolls back
    • After 5 failed scale attempts, circuit breaker opens — stops scaling up
    • Tracks memory usage to prevent OOM conditions

        Check if we should scale down.
        Parameters:
        activeRunners - the current number of JobQueueRunner threads

        maxLag - ms the oldest ready job has waited, logged with the action

      • evaluateScalingFeedback

        private void evaluateScalingFeedback(int currentRunners, int currentReadyJobs, long currentMaxLag, long currentAvgLag, long currentMessageDelay, boolean currentDroppedJobs)
        Evaluate whether the last scale-up actually helped. Checks multiple signals: avg lag, max lag, ready jobs, message delay, and dropped jobs. If any signal worsened beyond threshold, rolls back.
        Parameters:
        currentRunners - runner count now, caps how many added runners roll back
        currentReadyJobs - ready jobs now, compared with the pre-scale snapshot
        currentMaxLag - ms, worst ready-job lag now, compared with the snapshot
        currentAvgLag - ms average lag now, compared with the pre-scale average
        currentMessageDelay - ms message delay now, checked against pre-scale lag
        currentDroppedJobs - true when the queue has dropped jobs since the snapshot, which forces a rollback
