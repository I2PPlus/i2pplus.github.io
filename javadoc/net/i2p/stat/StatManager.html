    java.lang.Object
    net.i2p.stat.StatManager
    public class StatManagerextends Object
    Coordinate the management of various frequencies and rates within I2P components, both allowing central update and retrieval, as well as distributed creation and use. This does not provide any persistence, but the data structures exposed can be read and updated to manage the complete state.

      • _coalesceFailures

        private final AtomicLong _coalesceFailures
        Total coalesce failures isolated since startup, across all stats.

        Nonzero means at least one stat stopped recording. It is reported rather than absorbed because the failure it counts is silent by nature: a skipped rate produces no exception for anyone to notice.

      • _lastCoalesceSweepAt

        private volatile long _lastCoalesceSweepAt
        Clock value of the last completed coalesce sweep, or 0 if none has run.

        This is a heartbeat for the whole stat subsystem. The sweep runs on the shared coalesce timer, so it can stop without any exception: the task is simply queued behind other work and never runs. Nothing inside the stats package can detect its own non-execution, so an observer outside it needs this to tell "a rate failed to coalesce" apart from "no rate was asked to coalesce at all". GraphGenerator's health watchdog reads it, from a scheduler independent of the timer that could be wedged.

      • getOrCreateRateStat

        public RateStat getOrCreateRateStat(String name, String description, String group, long[] periods)
        Resolve a rate stat by name, creating it if it does not exist yet, and return the handle to it.

        Lets a caller reporting the same stat repeatedly avoid the string-keyed map lookup that addRateData(String, long) pays on every call. Resolution is check-then-act, not a single ConcurrentMap.computeIfAbsent(K, Function): the creation itself goes through createRequiredRateStat(String, String, String, long[]), which does use computeIfAbsent, so concurrent callers may both attempt it but exactly one stat is built and the delivery queue is attached before that stat is published. The handle is therefore usable the instant this returns.

        The handle is not invalidated when the stat is removed: a stale handle keeps updating an orphaned stat, which is inert rather than harmful, and detecting that would cost the lookup this exists to remove. It is valid until removeRateStat(String) or shutdown().

        Parameters:
        name - unique name of the statistic
        description - simple description of the statistic, used only if the stat has to be created
        group - used to group statistics together
        periods - array of period lengths (in milliseconds)
        Returns:
        the stat for name, or null if this manager is not collecting it and it does not already exist

      • getCoalesceSkips

        public long getCoalesceSkips()
        Sum of Rate.getCoalesceSkips() across every rate in the table.

        A rate normally skips one coalesce per period, so this grows steadily and is not by itself a problem. It is reported so that a rate which stopped coalescing entirely can be told apart from one that is merely visited early.

        Returns:
        total coalesce skips across all rates

      • getCoalesceBacklogCollapses

        public long getCoalesceBacklogCollapses()
        Sum of Rate.getCoalesceBacklogCollapses() across every rate in the table.

        Unlike a skip, a collapse is permanent: the steps it abandoned can never be written, so every count here is a gap in the graph data. Zero is the healthy state. A nonzero value points at the shared coalesce timer rather than at any one rate, since all rates are coalesced from the same SimpleTimer2 pool.

        Returns:
        total backlog collapses across all rates

      • getSampleOverruns

        public long getSampleOverruns()
        Samples evicted because the delivery queue hit its hard capacity.

        Unlike RateSampleDelivery.getSuperseded() this must never happen: same-step supersession means a slow consumer does not grow the queue, so reaching the cap means the consumer is not draining at all. Surfaced here because the delivery queue is package-private and the console watchdog, which is the only thing positioned to act on it, lives in another package.

        Returns:
        eviction count since startup, zero in the healthy state

      • getSampleSuperseded

        public long getSampleSuperseded()
        Samples replaced in place by a newer value for the same archive step.

        High but non-zero is normal under load and is not loss - only one value per step is storable and the newest is the correct one. A count that stops advancing while getSamplePending() climbs means the consumer has stopped draining.

        Returns:
        supersession count since startup

      • coalesceStats

        public void coalesceStats()
        Coalesce all rate stats and periodically coalesce frequency stats, isolating every stat from every other.

        Isolation is the whole point of this method. It runs as one pass over the whole table on the shared coalesce timer, so a single exception escaping a stat would abandon every stat later in the pass: their rates would stop coalescing, their listeners would receive nothing, and their graphs would freeze while every health check still reported them healthy. One broken stat must therefore be able to affect only itself.

      • getCoalesceSweepAgeMs

        public long getCoalesceSweepAgeMs(long now)
        How long ago the last coalesce sweep completed, or -1 if none ever has.

        Callers use this to distinguish a rate that will not coalesce from a coalesce task that is not running. A sweep older than a few rate periods means the latter, which no counter inside this package can report.

        Parameters:
        now - current clock value in ms
        Returns:
        ms since the last completed sweep, or -1 if there has never been one

      • noteCoalesceFailure

        private void noteCoalesceFailure(String statName, String period, Throwable cause)
        Count an isolated coalesce failure and log it, naming the stat at fault.

        ERROR rather than WARN because the failure is silent data loss, and logger.defaultLevel is ERROR: a WARN would be suppressed in a default configuration and the loss would go unnoticed. ERROR also reaches the console's error log page, so the stat is identifiable without reading the log file.

        Parameters:
        statName - name of the stat that failed
        period - the failing rate's period in ms, or null if not per-rate
        cause - what went wrong
