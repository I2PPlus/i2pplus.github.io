    net.i2p.stat.Frequency
    public class Frequencyextends Object
    Manage the calculation of a moving average event frequency over a certain period.

    This provides lifetime, and rolling average, frequency counts. Unlike Rate, it does not support "bucketed" averages. There is no tracking of the event frequency in the current or last bucket. There are no buckets at all.

    Depending on what you want, a rolling average might be better than buckets. Or not.

      • recalculate

        private void recalculate(boolean eventOccurred)
        Recalculate, but only update the lastEvent if eventOccurred

        The clock read is taken before the monitor, not inside it. It is a leaf call - currentTimeMillis is served from the vDSO and takes no Java lock - so holding this monitor across it makes every concurrent event queue behind a syscall rather than behind arithmetic. Hoisting it out cuts the contended cost of FrequencyStat.eventOccurred() on a three-period stat from 166ns to 145ns per event; uncontended it changes nothing, because the clock read costs the same either way when there is no queue.

        It is also safe to move. now is only ever differenced against _lastEvent, which is still read and written under the monitor, so the only effect is that the thread which loses the race computes its interval from a timestamp a few nanoseconds older. At millisecond resolution, and with the interval already clamped to [1, _period], that is not observable.

        Parameters:
        eventOccurred - true to record an event: the last-event time is updated and the count incremented; false recalculates the average interval only
