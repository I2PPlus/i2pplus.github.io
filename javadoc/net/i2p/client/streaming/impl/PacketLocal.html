      • getRttTime

        public int getRttTime()
        RTT sample for an ACKed packet: time between its last transmission and its ACK.

        Unlike getAckTime() (which measures lifetime since creation and is used for the stream.sendsBeforeAck stat), this excludes queueing delay: a packet may sit in the outbound queue (pacing, choke, slow tunnel) long after creation, and folding that delay into the RTT sample inflates SRTT and pins RTO at its ceiling exactly when recovery is needed. Per RFC 6298 section 3, only packets sent once are valid RTT samples; callers gate on getNumSends() <= 1 before trusting the value.

        Returns:
        the RTT sample in ms, or -1 if the packet was never sent or never ACKed

      • isAckStarvation

        static boolean isAckStarvation(boolean packetAcked, long highestAckedThrough, long ackProgressAtStart)
        Pure decision rule for the write-timeout ACK-starvation fail-fast.

        When a waitForCompletion reaches its write timeout with this packet still unacknowledged, the send should be treated as failed (rather than silently timing out and dropping the payload) only when the connection made no forward ACK progress at all while we waited. If any other packet was acknowledged during the window, the connection is slow but alive, and this packet's ACK is likely merely coalesced or lost — we must NOT fail it (avoid a false positive that would truncate a legitimate slow-but-progressing transfer).

        This was extracted as a pure static method so the fail-fast rule is unit-testable without a live Connection (mirrors the getAdaptiveSynTimeout evidence-gated pattern).

        Parameters:
        packetAcked - whether the specific packet was acknowledged (WriteStatus.writeSuccessful())
        highestAckedThrough - current connection-wide forward-ACK progress (Connection.getHighestAckedThrough())
        ackProgressAtStart - forward-ACK progress captured at wait start
        Returns:
        true if this is unambiguously ACK starvation and the send should fail fast; false if the connection made progress (or the packet was acked) and the send should be left to the normal timeout path

      • writeReleased

        public boolean writeReleased()
        Whether this packet's payload has been released and it can no longer be (re)transmitted.

        Both ackReceived() and cancelled() call releasePayload(), which returns this packet's buffer to the shared outbound payload cache and clears _payload. Once either has run the packet must never be enqueued again — a (re)send would read a null payload and crash the I2CP write. isCancelled() alone is insufficient: an ACKed-but-not-cancelled packet also has a released payload.

        This is the discriminator the retransmit timer uses to skip packets that were acknowledged or cancelled after it snapshotted the outbound set (a use-after-release TOCTOU between Connection.ackPackets and Connection.RetransmitEvent.timeReached), mirroring the paced-path guard on getAckTime().

        Returns:
        true if the packet was ACKed or cancelled, so its payload was released; false if it may still be transmitted
