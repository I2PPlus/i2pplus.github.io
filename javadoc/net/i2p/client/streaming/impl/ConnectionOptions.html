    I2PSocketOptions
    class ConnectionOptionsextends I2PSocketOptionsImpl
    Define the current options for the con (and allow custom tweaking midstream).

    Static fields with volatile and class-level setters (e.g., setInitialRTO(int), setMaxWindowSize(int)) are globally shared and adjusted by the Tuner. Per-connection fields are copied from these globals when a new Connection is created.

      • PROP_STALL_GIVEUP_MS

        static final String PROP_STALL_GIVEUP_MS
        How long an established connection may keep a packet in flight with no forward progress before it is force-closed, in ms.

        Deliberately its own setting rather than a product of maxResends and maxRTO. maxResends is the per-packet budget and governs loss tolerance; multiplying it by an RTO cap produced a four-minute connection lifetime as a side effect of a loss-tolerance knob. While the client tunnel pool is short of healthy tunnels, every second a dead stream is held is a second it occupies capacity that a live stream needs, and the resulting reconnects starve the pool further. Ninety seconds still rides out several firings past the RTO cap, so a genuinely transient loss survives.

      • defaultInitialRTO

        private static volatile int defaultInitialRTO
        Default initial RTO (ms) before any RTT measurement. Set to 9000 — accommodates typical I2P RTT up to ~6s without premature SYN retransmit, matching i2pd's INITIAL_RTO. The Tuner adjusts this adaptively based on network conditions.

      • maxRTO

        private static volatile int maxRTO
        Default 8000 accommodates RTT up to ~4s with standard TCP deviation. Shorter than the historical 30000 so a stalled path costs less: a lost packet blocks the stream head-of-line until its RTO backoff expires, and the Tuner only tightens this on paths that keep confirming sends. On a dead path (no confirmTime events) the Tuner sees no signal, so the code default IS the retransmit pace and the zombie-window backstop (maxResends * maxRTO) for that path. 8000 keeps each loss stall modest and the default 30-resend backstop (~4 min) inside a range a recovered path can still resume from, instead of the 15-min hang the 30s default gave. Tuner may raise this for very high-latency networks.
