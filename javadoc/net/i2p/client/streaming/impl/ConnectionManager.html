      • RTX_RATIO_RATES

        static final long[] RTX_RATIO_RATES
        Sample periods for the stream-close retransmission ratios. The five minute period is mandatory, not cosmetic: Tuner.getAdditionalStat5Min() reads exactly FIVE_MINUTES from both stats to measure routing congestion, and a RateStat without that period makes addRateData() silently drop those samples, leaving the tuner with NaN forever.

      • EVENT_RATES

        static final long[] EVENT_RATES
        Sample periods for the send-event counters whose ratio the streaming ceiling reads. The five-minute period is required so the event-count ratio can be compared against RTX_RATIO_RATES on the same window — without it the two signals live on different clocks and every comparison mixes a 60 s event figure with a 5 min byte figure.

      • PROP_TEMP_BAN_MINUTES

        public static final String PROP_TEMP_BAN_MINUTES
        Autoban property: a dest is temporarily banned until this many minutes after it first trips a flood threshold. Default 5 minutes. Short enough that a legitimate client's retry window (30s connect timeout) overlaps with the ban expiry, so retries succeed on the next attempt. The previous 24-hour default was far too aggressive: a burst of page-load SYNs from a browser (local or remote) could ban a peer for an entire day. Tunable via i2p.streaming.tempBanMinutes. 0 disables autoban. @since 0.9.71+.

        public static final String PROP_TEMP_BAN_RATE_MS
        Autoban property: a dest sending more than tempBanSynBurst SYNs within a tempBanSynRate-ms rolling window is auto-banned. This is the sub-second rate gate: a legit client (e.g. a BitTorrent announce on a timer) never bursts tens of SYNs within a few hundred ms, but the observed tracker flood does (~25 SYNs in 259ms).       • PROP_TEMP_BAN_SYN_BURST

        public static final String PROP_TEMP_BAN_SYN_BURST
        Autoban property: sub-second burst threshold (SYNs within rate window). Default 40 SYNs per 1s = 40 req/s instantaneous. A browser page load can fire 15-20 parallel connections, each with SYN retransmits; empty-response retry dual-race adds up to 4 SYNs/s per dest. The threshold must sit well above legitimate bursts so only a serious abuser trips it. First trip is a strike (no ban); a second trip within STRIKE_WINDOW_MS autobans.

      • PROP_TEMP_BAN_STRIKES

        public static final String PROP_TEMP_BAN_STRIKES
        Autoban property: how many DISTINCT burst windows inside STRIKE_WINDOW_MS a dest must trip before the SYN-burst gate autobans it. Default 3.

        A single burst window is not abuse: a browser page load, a client with a high concurrent-stream ceiling, or a peer resuming after a pause can all legitimately cross the sub-second threshold. Two was low enough that a merely busy peer could lose five minutes of connectivity, so the default demands sustained tripping of the gate. Raise it further on a high-legitimate-traffic router, or set PROP_AUTOBAN 0 to turn off autoban entirely (which also disables the refusal-based ban).

        Values below 2 are raised to 2: a single window must never ban alone. Tunable via i2p.streaming.tempBanStrikes.

      • reserveStreamSlot

        static boolean reserveStreamSlot(ConcurrentHashMap<Hash, AtomicInteger> ledger, Hash h, int max)
        Atomically take one stream slot from a dest's budget: the ceiling check and the increment happen inside a single per-key compute(), so two SYNs racing the gate can no longer both observe "room left" and admit past the ceiling (the check-then-add this replaced).

        Refusal leaves the counter untouched, so a rejected SYN never costs the dest anything. An unknown dest (null hash) is admitted without accounting, matching the old gate's "no hash, no budget" behavior.

        Parameters:
        ledger - the per-dest stream ledger, non-null
        h - remote dest hash, may be null
        max - the per-dest concurrent stream ceiling; ≤ 0 disables the gate
        Returns:
        true if the slot was taken (the caller now owns a slot and must either bind it to a reservation token or release it)

      • reconcileStreamCount

        static int reconcileStreamCount(int held, int observed, Integer candidate, int boundTokens)
        Pure reconciliation step for one dest: how much of a ledger count that exceeds the live connection table should survive this sweep.

        The excess is only dropped when the SAME excess was recorded by the previous sweep (the candidate), which means it persisted across a whole sweep interval and therefore cannot be an in-flight reservation admitted moments before the first sweep. Counts at or below the table are never raised: the ledger only ever shrinks toward observed reality, so a sweep can free leaked slots but can never hand out new ones.

        Even a repeated candidate cannot shrink below the bound-token floor. A release followed by a re-reserve can return the count to the same value while the observed snapshot still shows the old, smaller table (ABA): shrinking to observed there would erase brand-new reservations. Tokens are bound one-per-admission, so max(observed, boundTokens) is never below the live floor and a genuine leak (no token behind the excess) still shrinks to observed.

        Parameters:
        held - the count currently in the ledger
        observed - the count of live connections for the dest
        candidate - the excess last sweep recorded for this dest, or null
        boundTokens - reservation tokens bound for this dest right now
        Returns:
        the count to keep in the ledger this sweep

      • synBurstStrikeAction

        static ConnectionManager.SynBurstAction synBurstStrikeAction(ConnectionManager.SynStrike last, long windowStart, long now, long strikeWindowMs, int requiredStrikes)
        Pure decision for the multi-strike SYN-burst gate. Strikes mean DISTINCT burst windows: repeat trips inside the window that recorded the most recent strike are IGNOREd, so a single unlucky page-load burst can never cost a 5-minute outage however far over threshold it goes. Only when a dest has tripped requiredStrikes distinct windows inside STRIKE_WINDOW_MS of each other is this trip a BAN, i.e. the demonstrable pattern of sustained abuse. After the window the count is forgiven and a new one RECORDs instead.

        Forgiveness ages from the most recent strike time, so the window is rolling and the clock starts when the strike was recorded, not when the (millisecond-scale) burst window began.

        Parameters:
        last - recorded strike for this dest, or null if this dest has none
        windowStart - window start of the burst window that just tripped
        now - current clock time
        strikeWindowMs - strike forgiveness window (pass STRIKE_WINDOW_MS)
        requiredStrikes - distinct burst windows needed to ban; values below 2 are raised to 2 so a single window can never ban on its own
        Returns:
        the action to take for this trip

      • applySynBurstStrike

        static ConnectionManager.SynBurstAction applySynBurstStrike(ConcurrentHashMap<Hash, ConnectionManager.SynStrike> strikes, Hash h, long windowStart, long now, long strikeWindowMs, int requiredStrikes)
        Atomically evaluate and apply a burst-gate trip against h's recorded strike. The read-modify-write runs under ConcurrentHashMap.compute(K, BiFunction) so concurrent trips from one dest can neither both miss a just-recorded first strike (double-counting a single burst as two strikes) nor lose it to a racing put (letting a sustained flood escape the ban).
        Parameters:
        strikes - per-dest strike map
        h - remote dest hash, non-null
        windowStart - window start of the burst window that just tripped
        now - current clock time
        strikeWindowMs - strike forgiveness window (pass STRIKE_WINDOW_MS)
        requiredStrikes - distinct burst windows needed to autoban
        Returns:

      • checkInboundSynFlood

        boolean checkInboundSynFlood(Hash h, long now)
        Package-visible flood gate for the retransmit-SYN path in ConnectionHandler.receiveNewSyn(Packet). A retransmitted SYN carries the stream IDs of a connection that already exists in the manager, so it never reaches receiveConnection(Packet) (and thus never passes the checkSynBurst(Hash, long, boolean) gate at the top of that method). An attacker exploits that by planting a handful of half-open connections and then blasting retransmitted SYNs against them. Without this gate every hit makes ConnectionHandler.resendSynAck mint and enqueue a fresh SYN-ACK, consuming CPU and egress, and the connection never establishes.

        This routes the retransmit through the same per-destination sub-second burst window as fresh SYNs, so a dest that crosses the burst threshold in PROP_TEMP_BAN_STRIKES DISTINCT windows within the strike window — the demonstrable pattern of sustained abuse — is autobanned and dropped. A single burst only strikes, and with autoban disabled (PROP_AUTOBAN 0) nothing is recorded or dropped here. Once banned, subsequent calls return true (drop) immediately.

        Parameters:
        h - remote dest hash, non-null
        now - current clock time
        Returns:
        true if this SYN should be dropped (dest already temp-banned, or this SYN is a second distinct burst strike and just banned it)

      • limitResponse

        static String limitResponse(String limitAction, int retryAfter, boolean sslPort)
        The payload to send in a limit-response SYN/CLOSE, or null for a RESET.

        Pure decision helper (extracted from receiveConnection): the "reset" limit action, an empty action, and port 443 (the synth HTTPS over I2P port, which must not be tricked into a text payload) all produce a plain RESET. "http" produces an HTTP Retry-After body; anything else is echoed verbatim after normalizing \r/\code{n} escape sequences. HTTPS (443) always stacks the port check too, per RFC-compliant servers that disregard limit responses on that port.

        Parameters:

        retryAfter - seconds for the Retry-After header, or 0 to omit it
        sslPort - true if the SYN arrived on local port 443
        Returns:
        the response payload, or null for a RESET

      • publishLifetimeStats

        void publishLifetimeStats(Connection con)
        Publish a closing connection's lifetime counters.
