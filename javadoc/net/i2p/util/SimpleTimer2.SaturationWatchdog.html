    private class SimpleTimer2.SaturationWatchdogextends Object
    Samples this timer on its own daemon thread and reports a pool that has stopped keeping up.

    It cannot run on the pool it watches: a wedged pool has no spare worker to run the watchdog on, which is the whole failure. It also does nothing but read counters, so no event running on this timer can delay it. Every sample is four counter reads and a few field writes - no allocation, no synchronization beyond the monitor it sleeps on - so it is free to leave running for the life of the router.

    Everything below is touched only by the watchdog thread, except _stopped, which is guarded by the watchdog monitor.

      • start

        private void start()
        Start the sampling thread, warning if the JVM will not run it - a watchdog that silently failed to start is the same invisible failure this class exists to prevent. No reference to the thread is kept: it runs until shutdown(), and being a daemon it cannot hold up JVM exit either way.

      • shutdown

        void shutdown()
        Stop sampling. Idempotent, cannot throw, and safe when start() failed. The thread is a daemon, so it cannot hold up JVM exit even if this is never called.

      • run

        private void run()
        Sample every SimpleTimer2.WATCHDOG_INTERVAL_MS until shutdown().

        The stopped test and the wait share the monitor, so shutdown() cannot land between them and leave this thread parked for the rest of the interval - hence no interrupt is needed.

      • sample

        private void sample()
        Take one sample and act on it. All the executor counters are safe to read after shutdown, so a sample racing SimpleTimer2.stop() degrades to reporting nothing rather than throwing.

      • isWorkDue

        private boolean isWorkDue()
        Is a task actually due on this timer right now?

        A pool that has completed nothing may be idle or wedged, and completion counts cannot tell them apart - only this can. It is a property of the work offered, not of the timer's history, so unlike a calibrated gap threshold it cannot be tuned into uselessness by a timer that has always been quiet: a streaming retransmission shard that simply has nothing to retransmit has no due task and is correctly silent, while a shard with a due task and no progress is the thing worth reporting.

        Returns:
        true if the queue holds a task whose delay has already elapsed

      • checkStall

        private void checkStall(long completed, boolean workDue)
        Warn once per episode of a pool that completes nothing at all.

        The bar is the timer's own longest observed gap, learned as the timer comes and goes, rather than its mean interval. See SimpleTimer2.evaluateStall(long, long, int, int, boolean, long).

        Parameters:
        completed - the total number of tasks completed so far
        workDue - true if a task is due to run right now
