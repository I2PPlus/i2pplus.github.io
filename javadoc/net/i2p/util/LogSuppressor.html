    net.i2p.util.LogSuppressor
    public class LogSuppressorextends Object
    Collapses repeated occurrences of the same log message.

    Some conditions repeat thousands of times a minute - a peer resetting a connection, a tunnel failing to build - and each occurrence is individually uninteresting while the volume hides the messages that matter. At a few thousand lines a minute the log also stops being readable during an incident and starts costing real disk through rotation.

    A caller passes a stable key identifying the condition and logs through Log.warnThrottled(String, String) and friends. The first occurrence is always written; after that, an occurrence is written when either enough repeats have accumulated (DEFAULT_BURST) or enough time has passed (DEFAULT_WINDOW_MS), whichever comes first, and the line states how many were collapsed. A condition that fires once an hour is never hidden; one that fires two thousand times a minute is reduced to a couple of lines a minute that still say how big it was.

    Keys are scoped to the Log instance, which LogManager caches per class, so state is effectively per logging class and keys cannot collide across classes. The key table is bounded: entries whose window has long expired are pruned when it grows past MAX_KEYS, so a caller that keys on something unique per occurrence - a peer hash, say - cannot leak.

    Instances are thread-safe.

    • Method Details

      • isDue

        static boolean isDue(long occurrences, long lastReportCount, long lastReportMs, int burst, long windowMs, long nowMs)
        Decide whether one occurrence of key should be written.

        Pure, so the policy can be pinned by test without a clock or a logger. The first occurrence of a key always reports; afterwards a report is due once the repeats since the last one reach burst, or once windowMs have passed - time as well as count, so a slow trickle stays visible.

        Parameters:
        occurrences - total occurrences of this key including this one
        lastReportCount - occurrence count at the previous report, zero if never
        lastReportMs - wall-clock ms of the previous report, zero if never
        burst - repeats to accumulate before reporting again
        windowMs - longest a repeat may stay hidden
        nowMs - current wall-clock ms
        Returns:
        true if this occurrence should be written

        Drop bookkeeping for keys that can no longer report.

        Called on every recorded occurrence once the table is over its cap, so a caller that keys per-occurrence settles at the cap instead of growing forever. Cheap because it only runs when the table is already large.
