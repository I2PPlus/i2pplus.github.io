    public abstract class ImageWorkerextends Object
    Abstract base class for image workers in RRD graphs. Provides drawing operations for creating graph images with various output formats. Tracks last paint/stroke/font to avoid redundant state changes that produce duplicate inline styles in SVG output.

      • reduceVertices

        static int reduceVertices(double[] x, double[] y, int from, int to, boolean reverse, int[] xDev, int[] yDev, int c)
        Append the step-collapsed vertices of y over [start, end) into xDev/yDev, continuing from index c.

        A run of samples sharing a value is emitted as a single segment rather than as one vertex per sample, which is what gives the plots their staircase shape: a flat stretch becomes one horizontal line and each value change becomes one near-vertical line. Both the step and the smoothed renderer reduce the same way, so they always describe the same data.

        The caller owns the buffers. Continuing from an existing c lets the two boundaries of a filled area share one dedup pass, so a vertical side edge collapses into the adjacent vertex instead of contributing a redundant one.

        Parameters:
        x - the x coordinates
        y - the y coordinates to reduce
        from - first sample index of the range, inclusive
        to - one past the last sample index of the range, exclusive; the same exclusive bound in both directions
        reverse - true to walk from to - 1 down to from instead of upwards
        xDev - destination x coordinates
        yDev - destination y coordinates
        c - index to start writing at
        Returns:
        the new write index

      • runAnchorX

        static int runAnchorX(double[] x, int start)
        Leftmost column a run of samples may be drawn at, matching where the step renderer anchors the same run.

        The step renderer feeds reduceVertices(double[], double[], int, int, boolean, int[], int[], int) a doubled x array, in which every sample's x is written twice, and a y array whose trailing NaN is overwritten by the value that follows it. A run that therefore begins just after a NaN sample starts one index early, on the NaN sample's own x, so the step path's first point is drawn at that earlier column. The smoothed renderer uses one x per sample and keeps its NaNs, so without this correction its run would begin at the first valid sample instead - exactly one sample period to the right, which is visible as a gap at the start of the trace and grows with the plot's sample spacing.

        Anchoring on x[start - 1] is the same rule for every run, whether the preceding sample is the leading edge of the window or the far side of a gap, because the doubled x array maps both to the same index. When the run starts at the first sample there is no preceding sample and the run simply starts at its own column, which is at or just left of the plot area's clipped left edge, so the trace covers the whole width.

        Parameters:
        x - the sample x coordinates, one per sample
        start - first sample index of the run, inclusive, as returned by PathIterator.getNextPath()
        Returns:
        the column the run's first vertex must be drawn at

      • smoothedRun

        static GeneralPath smoothedRun(double[] x, double[] y, int start, int end, int[] xDev, int[] yDev, int transitionWidth)
        Builds the smoothed curve through one gap-free run of samples: the run is reduced to step-collapsed vertices, anchored and widened, and then interpolated.

        Extracted from drawPolylineSmooth(double[], double[], Paint, Stroke) and fillPolygonSmooth(double[], double, double[], Paint), which were identical up to the closing edges, so that a test can inspect the control points the renderer really emits. That has to be done here rather than on the rendered SVG, because the emitted path data is a compressed relative form whose numbers are not the control points.

        A cubic Bezier stays inside the convex hull of its four control points, so a curve that keeps both control point y values inside the band of its own two endpoints cannot leave that band. MonotoneSpline is what guarantees it: every tangent is limited to at most three times the interval's secant, which bounds a control point's displacement from its endpoint by the distance between the two endpoints.

        Parameters:
        x - the sample x coordinates, one per sample
        y - the sample y coordinates for this run
        start - first sample index of the run, inclusive
        end - one past the last sample index of the run, exclusive
        xDev - scratch buffer for the reduced vertices, at least end - start long
        yDev - scratch buffer for the reduced y coordinates, same length as xDev
        transitionWidth - most width, in pixels, to give one sub-pixel transition
        Returns:
        the curve, or null when the run reduced to fewer than two vertices and so has nothing to draw

      • fillPolygonSmooth

        void fillPolygonSmooth(double[] x, double yBottom, double[] yTop, Paint paint)
        Fill an area with a flat lower boundary, drawn as a smoothed curve.

        The outline is emitted as a single closed subpath: the smoothed upper boundary forward, then down to the baseline and back along it. One subpath is required rather than two open ones, because SVG closes each subpath implicitly and two overlapping windings under the default nonzero rule would cancel and leave a hole.

        The smoothed curve cannot rise above the baseline. It is confined to the vertical band between the two samples it joins, and every sample is at or above the baseline the graph is drawn from, so the outline cannot fold back on itself.

        Parameters:
        x - the x coordinates
        yBottom - the flat lower boundary
        yTop - the top y coordinates
        paint - the paint to fill with
