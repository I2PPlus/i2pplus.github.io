    public class Peerextends Object implements Comparable<Peer>, BandwidthListener
    Represents a peer in the BitTorrent network, managing all public information and communication with that peer.

    This class handles:

    • Peer identification and handshaking
    • BitTorrent protocol communication
    • Upload/download statistics tracking
    • Connection state management
    • Bandwidth monitoring and limiting

    Peers can be either incoming (they connected to us) or outgoing (we connected to them) connections.

        public Peer(I2PSocket sock, InputStream in, OutputStream out, byte[] myId, byte[] infohash, MetaInfo metainfo) throws IOException
        Incoming connection. Creates a unconnected peer from the input and output stream got from the socket. Note that the complete handshake (which can take some time or block indefinitely) is done in the calling Thread to get the remote peer id. To completely start the connection call the connect() method.
        Parameters:
        sock - the connected socket the handshake runs over
        in - the stream the handshake is read from
        out - the stream the handshake is written to

        infohash - the info hash of the torrent
        metainfo - null if in magnet mode
        Throws:
        IOException - when an error occurred during the handshake.

      • runConnection

        public void runConnection(I2PSnarkUtil util, PeerListener listener, BandwidthListener bwl, BitField bitfield, MagnetState mState, boolean uploadOnly)
        Runs the connection to the other peer. This method does not return until the connection is terminated.

        When the connection is correctly started the connected() method of the given PeerListener is called. If the connection ends or the connection could not be setup correctly the disconnected() method is called.

        If the given BitField is non-null it is send to the peer as first message.

        Parameters:
        util - the utility holding this client's connection settings
        listener - notified when the connection is established or ends
        bwl - the bandwidth limiter this peer's traffic is accounted against
        bitfield - the bitfield sent as the first message, or null to send none
        mState - the magnet state recording this peer's piece availability
        uploadOnly - if we are complete with skipped files, i.e. a partial seed
