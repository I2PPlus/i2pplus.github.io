I2P+ Глоссарий

Термины I2P из раздела справки I2P+

Адресная книга
Веб-приложение I2P, которое управляет назначениями сервисов для сети, сопоставляя хеши B64 человекочитаемым именам. Назначения могут быть добавлены вручную или через подписки на файлы hosts.txt. Также известно как SusiDNS. Подробнее см. онлайн-документацию.

Base32 (B32) / Base64 (B64)
Base32 ссылка (всегда заканчивается на .b32.i2p) — это хеш Base64 назначения. Для сервисов в сети хеш Base64 часто сопоставляется с доменом .i2p в адресной книге.

BOB
BOB (Basic Open Bridge) — простой протокол приложение-маршрутизатор, в значительной степени вытесненный SAM. Подробнее см. онлайн-документацию.

表网 (Clearnet)
表网 обычно относится к публично доступному интернету, противоположность даркнета, который обычно описывает зашифрованные анонимные сервисы на базе I2P, Tor и т.д. Подробнее см. статью в Wikipedia.

Назначение (Destination)
Уникальный криптографический идентификатор входного конца туннеля, предоставляющего доступ к сервису в сети I2P, представленный в виде Base32 или Base64 хеша публичного ключа. Аналог IP-адреса и порта.

Eepget
Приложение командной строки, поставляемое с I2P, используемое для запроса URL-ресурсов, аналогичное wget или curl. Eepget также используется маршрутизатором внутренне, например, для пересеивания с удалённых хостов. По умолчанию eepget использует HTTP-прокси на 127.0.0.1:4444.

Eepsite
Веб-сайт, размещённый в сети I2P. По умолчанию веб-сервер Jetty настроен и работает на http://127.0.0.1:7658/.

Исследовательский туннель
Туннель, используемый маршрутизатором для связи с другими маршрутизаторами для выполнения различных функций «обслуживания», таких как изучение и публикация наборов租约, тестирование клиентских туннелей, а также изучение и проверка других маршрутизаторов в сети. Эти туннели обычно имеют низкую пропускную способность.

Floodfill/Затопление
Маршрутизатор в сети, задача которого — предоставлять и получать информацию о других маршрутизаторах в сети. Текущая минимальная пропускная способность для маршрутизатора, чтобы считаться способным выполнять функции затопления, составляет 128 КБ/с, хотя можно отменить это требование и принудительно включить затопление на странице расширенной конфигурации. Подробнее см. онлайн-документацию.

Чесночный маршрутиз (Garlic Routing)
Вариант лукового маршрутиза, который шифрует несколько сообщений вместе, чтобы затруднить анализ трафика атакующими и повысить скорость передачи данных. Подробнее см. онлайн-документацию.

Скрытый режим
Маршрутизатор, настроенный на работу в скрытом режиме, не публикует свои данные в Сетевой базе данных и не участвует в маршрутизации трафика для других маршрутизаторов. Маршрутизаторы, работающие в странах, обозначенных как строгие, и маршрутизаторы, настроенные вручную, работают в скрытом режиме.

I2CP
Протокол клиента I2P (I2CP) позволяет внешним приложениям (клиентам) взаимодействовать с I2P через единственный TCP-сокет, по умолчанию используя порт 7654. Подробнее см. онлайн-документацию.

I2NP
Сетевой протокол I2P (I2NP) управляет маршрутизацией и смешиванием сообщений между маршрутизаторами, а также выбором транспорта (при поддержке нескольких) при взаимодействии с пиром. Подробнее см. онлайн-документацию.

I2P+
Мягкая ветка программного обеспечения Java I2P, сохраняющая полную совместимость, обеспечивающая улучшенный пользовательский интерфейс и повышение производительности сети. Подробнее см. http://skank.i2p/static/i2p+.html.

I2PBote (плагин)
Плагин I2P, обеспечивающий серверный, сквозно-шифрованный электронный почтовый сервис в сети I2P. Сайт: http://bote.i2p/. Исходный код доступен на github.

i2pd
Альтернативная реализация маршрутизатора I2P, написанная на C++. Подробнее см. https://i2pd.website/.

I2PSnark
Форк BitTorrent-клиента Snark, адаптированный для использования в сети I2P. Обычно поставляется как часть стандартного набора приложений Java I2P, а также доступен как автономное Java-приложение.

Вводящий (Introducer)
Маршрутизатор, облегчающий подключение к сети другого маршрутизатора, находящегося за файрволом.

Сервис переключения (Jump Service)
Простое CGI-приложение, принимающее имя хоста в качестве параметра и возвращающее 301-редирект на правильный URL с附加лой строкой ?i2paddresshelper=key. HTTP-прокси интерпретирует附加лую строку и использует ключ как фактическое назначение. Кроме того, прокси кэширует ключ, поэтому адресный хелпер не необходим до перезапуска, и предлагает вариант добавления разрешённого адреса в адресную книгу.

Режим ноутбука (Laptop Mode)
Опциональная конфигурация, автоматически изменяющая идентификатор маршрутизатора и внешний порт при изменении публичного IP-адреса вашей системы. Это может помешать противнику связать ваш идентификатор маршрутизатора и IP-адрес в сценариях, где ваш IP-адрес может часто меняться, например, при запуске I2P на ноутбуке из разных мест.

Аренда (Lease)
Информация, определяющая авторизацию конкретного туннеля на приём сообщений, предназначенных для определённого Назначения.

Набор аренд (LeaseSet)
Группа точек входа в туннель (аренд) для назначения. Примечание: серверный туннель с 0 хопами будет иметь только одну аренду, независимо от количества настроенных туннелей.

Monotone / mtn
Распределённая система контроля версий (DVCS), используемая для поддержания исходного кода I2P. Подробнее см. онлайн-руководство.

Мультихоминг (Multihoming)
Сервисы могут быть размещены на нескольких маршрутизаторах одновременно путём совместного использования одного и того же приватного ключа для назначения. Мультихоминг может进一步 улучшить безопасность и стабильность сервера за счёт обеспечения избыточности; если сервер является мультихомным, когда сервер в пуле.offline, предоставляемый сервис останется доступным, что затрудняет коррелацию времени простоя сервера с.offline маршрутизатора.

Сетевая база данных (Network Database)
Распределённая база данных, содержащая контактную информацию маршрутизаторов (RouterInfos) и контактную информацию назначений (LeaseSets). Один маршрутизатор поддерживает свою собственную (частичную) базу данных для взаимодействия с другими маршрутизаторами в сети; ни один маршрутизатор не поддерживает список всех маршрутизаторов. RouterInfos хранятся на диске и считываются в память при запуске маршрутизатора или при получении новых RouterInfos. Также известна как NetDb. Подробнее см. онлайн-документацию.

NTCP / NTCP2
NTCP (на основе NIO TCP) и NTCP2 — это транспорты на основе TCP, которые используют реализацию TCP Java NIO (New I/O) для доставки сообщений I2NP между маршрутизаторами в сети. NTCP2 повышает устойчивость NTCP к различным атакам и методам автоматической идентификации трафика. Подробнее см. онлайн-документацию.

Orchid (плагин)
Java-реализация клиента Tor, доступная как плагин I2P. Может использоваться как выходной прокси по умолчанию, если настроен в соответствующем SOCKS или HTTP клиентском туннеле в Менеджере туннелей. Доступен на http://stats.i2p/i2p/plugins. Исходный код доступен на github.

Выходной прокси (Outproxy)
Сервис в сети, обеспечивающий прокси-соединение с 表网. По умолчанию I2P настроен на HTTP-выходной прокси для веб-сёрфинга на 127.0.0.1:4444.

Участие в ретрансляции (Participation)
Действие по вкладу в сеть путём разрешения другим маршрутизаторам строить туннели с использованием вашего маршрутизатора в цепочке туннелей. Для включения участия необходимо выделить как минимум 12 КБ/с восходящей пропускной способности (сетевая доля). Обратите внимание, что маршрутизаторы за файрволом будут ограничены в том, как много они вносят в участие, а маршрутизатор, обозначенный как Скрытый, не будет участвовать вообще.

Пересеивание (Reseeding)
Процесс получения идентификаторов маршрутизаторов, обычно через серверы 表网, чтобы обеспечить возможность вашего маршрутизатора взаимодействовать и строить туннели с другими маршрутизаторами в сети. Когда у маршрутизатора нет идентификаторов маршрутизаторов для других пиров (обычно сразу после установки), процесс пересеивания также называется bootstrapping (начальная загрузка).

Маршрутизатор
Основное программное обеспечение I2P, которое маршрутизирует зашифрованные пакеты в сети I2P. Все маршрутизаторы по умолчанию участвуют в сети, за исключением маршрутизаторов, работающих в странах, считающихся враждебными (см. Строгие страны), что как помогает сети, так и обеспечивает прикрывающий трафик для любых клиентов или серверов, подключающихся к сети I2P через маршрутизатор.

Идентификатор маршрутизатора (Router Identity)
Информация, определяющая уникальный идентификатор маршрутизатора в сети, включая его IP-адрес (или IP-адреса промежуточных вводящих) и прослушиваемый порт, публичные ключи подписи и шифрования. Идентификаторы маршрутизаторов соответствуют пирам в NetDB. Также известен как RouterInfo.

SAM
SAM (Simple Anonymous Messaging) — протокол, позволяющий клиентскому приложению, написанному на любом языке программирования, взаимодействовать через I2P, используя сокетный интерфейс к маршрутизатору I2P. Подробнее см. онлайн-документацию.

SSU
SSU (Secure Semi-reliable UDP) — транспорт сети I2P, обеспечивающий зашифрованные, ориентированные на соединение, точка-точка соединения, а также的服务 по обнаружению IP-адресов и обходу NAT. Подробнее см. онлайн-документацию.

Строгие страны (Strict Countries)
Список стран, полученных из World Freedom Report, с плохой репутацией в области гражданских свобод. Этот список используется для перевода маршрутизаторов, работающих в указанных странах, в скрытый режим для обеспечения повышенной безопасности пользователей. Следующие страны обозначены как строгие: Афганистан, Азербайджан, Бахрейн, Беларусь, Бруней, Бурунди, Камерун, ЦАР, Чад, Китай, Куба, ДРК, Египет, Экваториальная Гвинея, Эритрея, Эфиопия, Иран, Казахстан, Лаос, Ливия, Мьянма, Северная Корея, Палестинские территории, Руанда, Саудовская Аравия, Сомали, Южный Судан, Судан, Эсватини (Свазиленд), Сирия, Таджикистан, Таиланд, Турция, Туркменистан, Венесуэла, ОАЭ, Узбекистан, Западная Сахара, Йемен.

Туннель
Однонаправленный зашифрованный маршрут связи между клиентом или сервером в сети I2P. Аналогичен цепочке в Tor, за исключением того, что цепочки Tor являются двунаправленными.

Конечная точка туннеля (Tunnel Endpoint)
Последний маршрутизатор в туннеле, который может быть исходной конечной точкой, где клиентские туннели встречаются с входным шлюзом серверных туннелей назначения, или входной конечной точкой, которая является последним маршрутизатором в цепочке, подключающимся к серверу назначения.

Шлюз туннеля (Tunnel Gateway)
Первый маршрутизатор в туннеле. Для входных туннелей это тот, который упоминается в наборе租约, опубликованном в Сетевой базе данных. Для исходных туннелей шлюзом является инициирующий маршрутизатор.

Менеджер туннелей (Tunnel Manager)
Веб-приложение, поставляемое с маршрутизатором, позволяющее создавать и настраивать клиентские и серверные туннели. Также известно как Менеджер скрытых сервисов.

Участник туннеля (Tunnel Participant)
Маршрутизатор в туннеле, не обозначенный как шлюз или конечная точка.

ZzzOT (плагин)
Реализация Java I2P плагина для BitTorrent Open Tracker. Доступен на http://stats.i2p/i2p/plugins. Исходный код доступен на github.
